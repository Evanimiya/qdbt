# QDBT 계획 — 부품(BOM) 이중 경제구조 (2026-07-13, 확인용)

> 원칙: 비파괴 · **총액 Δ=0(부품 파트금액 이중계상 금지)** · 정본 불변 · 매칭 3단계 · 검증 게이트.
> 부품은 데이터모델·경제구조라 **구현 전 확인**. 아래 확정 후 (부품 반영 포함) #4→#3→#2 순 구현.

## 1. 현행 부품 처리 (파악)

- `column_mapping`에 **`part` 역할(부품 '이름'만)** 존재. `part_qty/part_price/part_amount` 역할 **없음**.
- `extract_by_mapping`·`stitch._part_promote`: 부품 값이 있으면 **품목(name)을 분류 경로로 내리고 부품을
  잎으로** 승격(path만 깊어짐). 잎(부품)이 그 **행의 qty/price/amount** 를 그대로 보유.
- 결과 문제: **품목 자신의 행이 없다**(품목은 경로 노드일 뿐). 총액 = Σ(잎=부품 amount) →
  시트가 파트금액을 amount로 매핑하면 **총액=Σ파트금액**(품목수량 누락·breakdown을 총액으로 오계상).
  경제 롤업(단가=Σ파트금액, 금액=수량×단가)·검증 **없음**. → BOM 이중구조 **미지원**.

## 2. 제안 데이터 모델 (BOM)

### 역할(신규)
- 품목 레벨(기존): `qty`(품목수량) · `price`(품목단가) · `amount`(품목금액=수량×단가).
- 부품 레벨(신규): `part`(부품명) · **`part_qty`(부품수량)** · **`part_price`(부품단가)** ·
  **`part_amount`(파트금액=부품수량×부품단가)**.

### 행(row) → 항목(item) 매핑
- **품목 = 총액 집계 잎**: 1 submission_items 행. path=분류, name=품목, qty/price/amount=품목값.
  `is_header=0`(총액 포함). 레벨=품명(5).
- **부품 = 품목 하위 표시노드**: 부품마다 1 행. path=분류 > 품목, name=부품,
  part_qty/part_price/part_amount 보유(표시), amount=파트금액(표시용). **`is_header=1` + `bom_part` 표식
  → 모든 합계 쿼리에서 제외(이중계상 방지)**. 레벨=부품(6).
- 품목 식별/그루핑: 같은 품목명(또는 품목 seq/행 그룹) 아래 부품 0..N. 부품 없으면 품목이 곧 잎(현행 동일).

### 롤업 규칙 (표시·검증용, 정본 불변)
- **품목단가(per-unit) = Σ(파트금액)** — 1대분 BOM 원가.
- **품목금액 = 품목수량 × 품목단가**.
- **총액 = Σ(품목금액)** = Σ(수량×단가). 부품 파트금액은 단가의 breakdown → **총액 미포함**.

## 3. 불변식 · 검증 게이트 (`core/totals` 확장)

행별 검증(있는 값만, tol 허용):
1. **BOM 원가**: `Σ파트금액 ≈ 품목단가`  (불일치 → residual/경고 `bom_cost_mismatch`).
2. **라인 정합**: `품목수량 × 품목단가 ≈ 품목금액` (기존 `check_line_amounts` 재사용).
3. **총액**: `Σ(is_header=0 품목금액) ≈ 공급가액`(기존 `check_supply_total`). 부품 제외로 이중계상 0.

per-unit vs total 표기 애매성 **감지·플래그**:
- `Σ파트금액 ≈ 품목단가` → **per-unit(정상, 사용자 설명)**.
- `Σ파트금액 ≈ 품목금액(=수량×단가)` → 파트금액이 이미 총량 스케일 → `bom_scale_ambiguous` 플래그
  (사용자 확인). 자동 변환 안 함(3단계: 사람 확정).

## 4. 이중계상 방지 (어디서 보장하나)

- **부품 행 `is_header=1`** → `get_items(headers=False)`·`recompute_subtotal`·모든 합계 쿼리에서 자동 제외
  (기존 merge_status와 동일 메커니즘). 품목 금액만 합산 → **총액 Δ=0**.
- 부품은 트리·엑셀·캔버스에 **표시**되되 금액 집계엔 불참(파트금액은 단가 내역 표시로만).

## 5. 미니 예시

```
분류        품목    품목수량 품목단가 금액     | 부품    부품수량 부품단가 파트금액
재료비 > 차폐 납블록   2       300     600     |
   └ 부품                                       | 순납강판  3       50      150
   └ 부품                                       | 볼트      1      150      150
```
- Σ파트금액 = 150+150 = 300 = 품목단가 ✓(per-unit). 품목수량×단가 = 2×300 = 600 = 금액 ✓.
- **총액 = 600**(품목금액). 부품 파트금액(300)은 **더하지 않음**.
- 트리/캔버스: `재료비 > 차폐 > 납블록(품명) > {순납강판, 볼트}(부품)`. 캔버스 열: …품명|부품.

## 6. #2/#3/#4·레벨 캔버스 통합 반영

- **레벨 캔버스**: 부품=레벨6 → 의미열 그리드에 **'부품' 열** 자동 표시(이미 leaf-aware·col=level-1 지원).
  품목(품명 열)→부품(부품 열) 연결선. 부품 카드에 파트금액(단가 내역) 표기.
- **#3 레벨별 엑셀**: 열 = 대·중·소·세·품명·**부품** + (품목)규격·수량·단가·금액 + (부품)부품수량·부품단가·
  파트금액. 품목 행에 품목값, 그 아래 부품 행에 부품값. 상위 셀 병합. **합계행=Σ품목금액**(부품 제외).
- **#4 재레벨링**: 부품=레벨6 하한. 재레벨 클램프에 **부품 경계(6) 포함** — 품목(5) 아래로만, 순환 방지.
- **#2 재구성층**: 부품도 item_id 기반이라 recon 이동·비교/클러스터링 무영향(3단계 유지). 부품을 다른
  품목 아래로 옮기면 그 품목의 `Σ파트금액≈단가` 검증이 재평가되어 불일치 시 경고.

## 7. 확인 필요 (구현 전)

1. **행 구조**: 부품수량/단가/파트금액이 **부품 행에**, 품목수량/단가/금액이 **품목(첫/병합) 행에** 있는
   구조가 맞는지? 아니면 **한 행에 품목값+부품값 동시**(부품 여러 행이 품목값 반복)인지? → 실제 시트 1개
   샘플이 있으면 확실. (매핑 자동감지·그루핑 규칙이 여기서 갈림.)
2. **총액 기준**: 총액 = Σ품목금액(수량×단가) 확정 — 부품 파트금액은 절대 미포함. (확인)
3. **검증 tol**: `Σ파트금액≈단가`·`수량×단가≈금액` 허용오차(기본 1원/0.5%)와 불일치 시 **residual 표기 +
   경고**(자동 수정 안 함) — 이대로?
4. **부품 저장 컬럼**: 신규 `part_qty/part_price/part_amount`를 submission_items 컬럼으로 추가(자동
   마이그레이션) vs `cat_levels`처럼 표시 JSON 1컬럼(`bom` JSON)로? (권장: 검증·엑셀에 쓰므로 정식 컬럼.)

→ 위 확정되면 (부품 검증/롤업 코어 → 추출/스티칭 → 캔버스/엑셀) 작게 커밋. 총액 Δ=0 게이트·실샘플 회귀 유지.
