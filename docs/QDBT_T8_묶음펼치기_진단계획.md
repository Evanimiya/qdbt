## 1. 선결 점검 결과 — **T4는 잎 펼치기(표시)의 선결이 아니다**

로드맵상 T8이 T4 선결로 표시돼 있으나, 코드 진단 결과 **표시(펼치기)와 잎 재매칭은 T4 category-override 없이 정본 불변으로 안전하게 선행 가능**하다.

근거:
- **T4의 남은 되먹임은 오직 `category`(+`path`) write-back**이다(T4 진단서 1-2). 잎 펼치기·잎 재매칭은 **category를 바꾸지 않는다** → T4 override와 무관.
- **비교측 저장 테이블이 이미 분리돼 있다**: 클러스터 멤버십은 `catalog_cluster_members`(비교 WS 소유), 카탈로그 매칭은 `item_match`(version 차원) — 둘 다 정본을 안 건드림. 잎 재매칭은 이 비교측 테이블에만 쓴다.
- **잎 데이터는 이미 조회 시점에 존재**한다: `_apply_compare_units`가 만든 묶음 group에 `member_item_ids`(묶음이 품은 **모든 잎 item_id**)와 `amount`(=Σ잎, 구조적으로 합산됨)가 실려 있다(`queries.py:1425,1430,1443`). 즉 **잎을 보여주려면 submission_items를 읽기만** 하면 된다.

**결론**: 잎 펼치기(설계 1·2단계 = 표시)는 **정본 완전 불변·Δ=0**으로 지금 구현 가능. 잎 재매칭(3·4단계)도 정본 불변(cluster_members에만 기록)이나 클러스터 조작이라 이번 범위에서 제외(사용자 지침: 클러스터 대개편 금지). category를 실제로 바꾸는 조작이 잎 재매칭에 끼어들 때에만 T4가 필요.

## 2. 현재 구조 진단

### 2-1. 조회 (`queries.py:compare_bid_submissions`)
- `bid_clusters` → 각 클러스터의 `member_ids`(catalog_cluster_members) → `all_items`에서 매칭되는 항목 수집(`cluster_items`).
- 매칭 규칙(1630-1632): 항목 자신이 멤버이거나 **묶음의 잎 중 하나라도 멤버**(`member_item_ids & member_ids`)면 포함 → 묶음이 클러스터에 들어감.
- `cluster_items` → 이름/경로로 그룹화(`group_map`) → 업체별 셀(`cells: vendor→{item_id,unit_price,amount,quantity,...}`) → `groups`(멤버 행) → 클러스터별 `vendor_totals`(업체별 amount 합).
- **묶음 셀**: 셀의 `item_id`는 묶음 대표, `amount`는 Σ잎. 하위 잎 목록은 현재 **spec 문자열 요약**(`(3개: A, B, C)`)로만 존재 — **개별 잎의 item_id·금액은 셀에 없음**(설계서 3.1의 지적과 일치).

### 2-2. 표시 (`compare/bid.html`)
- 클러스터 헤드 셀(📦 대표명) + 업체별 가격 행렬. 멤버 행(groups)마다 업체 셀.
- **기존 "전체 펼치기"(line 184, `qdAllCats`)는 분류(카테고리) 레벨 토글** — 카테고리 하위 클러스터 행 show/hide. **묶음→잎 펼치기와는 다른 축**(카테고리 접기 ≠ 묶음 내부 잎 펼치기).
- 셀 클릭 `toggleCell`은 단가↔금액 표시 전환(통화 2단). 잎 펼치기와 무관.

### 2-3. 저장 (`catalog_clusterer.save_clusters`, `catalog_cluster_members`)
- `role ∈ {representative, duplicate}`(스키마 기본 'duplicate'). 설계대로 **'leaf' 값 추가는 스키마 변경 없이 가능**.
- 현재 클러스터 확정 시 잎은 보존되지 않음(대표 잎 하나 + 멤버는 이름 문자열).

## 3. 구현 계획 (이번 범위: 설계 1·2단계 = **표시 전용 잎 펼치기**, 정본 불변)

### 3-A. 조회 확장 — 묶음 셀에 잎 목록 부착 (읽기 전용)
`compare_bid_submissions`에서 묶음 셀(`is_unit_group`/`member_item_ids` 보유)에 대해, 그 잎 item_id들의 실제 행(name/spec/qty/unit_price/amount)을 `all_items`(또는 submission_items 조회)에서 모아 셀에 `leaves: [...]`로 부착.
- **정본 불변**: submission_items를 **읽기만** 함.
- **Σ잎 == 묶음 amount**: 이미 `_apply_compare_units`가 `amount = Σ(잎 amount)`로 구성 → 자동 성립. 조회 시 `assert`/경고로 검증(불일치 시 배지, 차단 안 함).
- 잎이 없는(단일 잎) 셀은 `leaves` 생략 → 펼침 버튼 미표시(회귀 없음).

### 3-B. 표시 — 묶음 셀에 펼침/접힘 토글 + 잎 행 렌더
- 묶음 셀(leaves 보유)에 **▸/▾ 펼침 캐럿**. 클릭 시 그 클러스터의 잎을 **중첩 행**으로 표시(업체 열 정렬 유지).
- 잎 행: 이름(`|leaf`) · 규격 · 단가/금액(통화 2단 재적용) · 최저가 하이라이트(잎 단위, 선택).
- **접힘/펼침 상태**: (결정 필요 ②) 기본 접힘 + 클라이언트 상태(세션스토리지) 유지 제안.
- **기존 "전체 펼치기"와 통합**: 별개 축이므로 **버튼 분리** — 기존 = "분류 펼치기"(라벨 명확화), 신규 = 묶음별 "잎 펼치기"(+ 선택적 "모든 묶음 펼치기" 전역 토글). 서로 독립 동작.

### 3-C. 소계 정합·총액 불변
- 클러스터 `vendor_totals`(업체별 Σamount)는 **잎 펼침과 무관하게 동일**(펼침은 표시일 뿐). 총액/소계 Δ=0.
- 잎 행 합 = 묶음 셀 amount 검증(표시용 경고).

### 3-D. (이번 제외, 후속) 잎 재매칭·스냅샷·이력
- **3단계(자동 재매칭)·4단계(수동 보정)·5단계(카탈로그·이력)**: 클러스터 조작/이력 입도 전환이라 이번 범위 밖. 모두 정본 불변(cluster_members·item_match에만 기록)이라 T4와 독립이나, "클러스터 대개편 금지" 지침에 따라 별도 진행.
- **role='leaf' 보존(1단계 데이터)**: 스냅샷/확정 시점에만 필요. **표시 전용 범위에선 조회로 대체 가능**하므로, 이번엔 저장 스키마를 건드리지 않고 조회로 처리(가장 additive). 스냅샷·재매칭 착수 시 role='leaf' 보존 추가.

## 4. 3대 불변 요건 충족 방식

| 요건 | 이번 구현에서 |
|---|---|
| ① 합계 보존 Σ잎==묶음 | `_apply_compare_units`가 이미 amount=Σ잎 → 조회 검증만. Δ=0 |
| ② 레벨 어긋남 흡수 | 표시 단계에선 "묶음 아래 잎 노출"까지. 잎↔잎 매칭(레벨 흡수 본체)은 후속 3단계 |

## 5. 결정 필요 항목 (착수 전 확인)

① **이번 범위 = 표시 전용(1·2단계)로 확정?** (권장: 예. 정본 불변·Δ=0·저위험. 잎 재매칭 3·4는 클러스터 조작이라 별도 승인 후)

② **펼침 상태 지속성**: (a) 세션스토리지 유지(새로고침해도 유지) / (b) 매번 접힘(단순) — (권장: a)

③ **잎 렌더 위치·형태**: (a) 클러스터 아래 **중첩 행**(업체 열 정렬 그대로, 권장) / (b) 별도 상세 패널/모달 / (c) 셀 툴팁. — 업체별 잎 개수 상이(E 3개·D 1개) 시 (a)는 "잎 클러스터 기준 행 + 빈 셀 허용"(설계 6 리스크 대응) 필요.

④ **잎 최저가 표시**: 잎 행에서도 업체 간 최저가 하이라이트할지(잎 단위 비교) / 묶음 단위만 유지할지. (권장: 잎 단위도 표시하되 매칭 없는 상태에선 "같은 이름 잎"만 비교, 오매칭 방지)

⑤ **role='leaf' 물리 보존 시점**: 이번엔 조회로만(스키마 무변경) vs 지금 저장까지. (권장: 이번엔 조회. 스냅샷/재매칭 착수 시 저장 추가)

⑥ **"전체 펼치기" 라벨/동작**: 기존 버튼을 "분류 펼치기"로 명확화 + 신규 "잎 펼치기" 분리 배치. (권장: 분리)

## 6. 리스크·검증 계획

- **Δ=0**: 잎 펼침은 표시 전용 → 총액/소계/최저가(묶음) 불변. 15샘플 + 3차 입찰 비교 화면 총액 회귀 없음 확인.
- **정본 불변**: submission_items write 0건(grep 게이트). 조회만.
- **회귀 없음**: 단일 잎 셀은 펼침 버튼 미표시 → 기존 화면 동일. 기존 "전체 펼치기(분류)"·`toggleCell`·정렬·통화 2단 동작 불변.
- **업체별 잎 개수 상이**: 행 정렬 붕괴 방지(잎 매칭 전이므로 "이름 기준 그룹 + 빈 셀"로 표시, 매칭은 후속).
- **되돌리기**: 조회 확장 + 템플릿/JS 추가뿐 → revert 용이. 스키마·정본 무변경.
