# QDBT 버그 테스트 보고서 — 실파일 품목이 '소분류'로 오분류 (C3_v2_real, 2026-07-12)

## 1. 증상 (사용자 제보 · 실파일 업로드)

`tests/rob/fixtures/C3_v2_real.xlsx` (3시트, 점 계층 번호):
- **공종목록**: 번호 `1,2,3,4` → 공종명(대분류: 컴퓨팅 인프라 등) + 금액
- **산출내역**: 내역번호 `1.1.1, 1.1.2, 1.2.1…` → 항목명(중-소 결합명 "GPU 컴퓨팅 - GPU 서버 노드") + 소계
- **세부산출**: 내역번호 `1.1.1.1…` → **품목**(GPU Server 등) + 규격·단위·수량·단가·금액 = 진짜 라인아이템(잎)

화면: 트리가 **대분류(공종) / 중분류(산출) / 소분류=GPU Server·InfiniBand·Mgmt Server** 로 나옴 —
**세부산출의 품목(잎)이 '소분류' 열에 표기**. 기대: **대 > 중 > 품명(잎)**. ("숫자 구분 지정했는데 에러".)

## 2. 정확 재현 (각 노드 depth·leaf·라벨)

번호 계층: `1`(공종/대) → **[1.1 없음 · gap]** → `1.1.1`(산출/중-소) → `1.1.1.1`(세부/품목·잎).

| 지점 | (수정 전) 실제 | 판정 |
|---|---|---|
| `stitch_workbook` (auto) | `path='GPU 컴퓨팅 - GPU 서버 노드 > GPU Server'` — **대분류(공종) 소실**, 2레벨 | ❌ 구조 A |
| `build_items_tree` | GPU Server = `is_leaf=True` (구조상 **잎은 맞음**) | 구조 정상(잎) |
| 연계 캔버스 열 헤더 | 3레벨일 때 품목 잎이 depth2 → `levelName(2)='소분류'` | ❌ 표시 B |

→ **두 개의 결함이 겹침**: (A) 대분류가 트리에서 소실, (B) 품목 잎 열이 '소분류'로 오라벨.
품목은 **항상 `is_leaf=True`**(구조상 잎). 문제는 대분류 소실 + 열 라벨.

## 3. 근본 원인

### (A · 구조) 대분류(공종) 소실 — seqmap 이름소스 누락
`_stitch_seq`는 번호 prefix→이름을 `seqmap`으로 조립한다. 이름소스를 `role ∈ {seq_list,
seq_tree, seq_leaf}` 시트로만 모았다. **공종목록은 번호+공종명+금액**을 가져 `_classify_sheet`가
`has_item=True`(금액 포함, 코드리뷰 M19) → **role='leaf'** 로 분류 → seqmap 이름소스에서 제외.
그 결과 번호 `(1,)`(대분류) 이름(컴퓨팅 인프라)이 seqmap에 없어, 세부 `1.1.1.1`의 부모 조립 시
`(1,)`을 건너뛰고 `(1,1,1)`(산출)부터 붙어 **대분류가 소실**(gap `1→1.1.1`과 겹쳐 악화).

### (B · 표시) 품목 잎 열이 '소분류'
연계 캔버스(`_link_canvas.html`)가 열 헤더를 `levelName(depth)`(고정 위치매핑 대/중/소/세/품명)로
라벨 → 분류 레벨이 적은 트리에서 품목 잎이 낮은 depth에 놓여 '소분류'로 오라벨.
(2026-07-11 커밋 `c9c78ce`에서 leaf-aware 라벨로 선수정한 것과 동일 원인.)

## 4. 수정

### (A) `src/extractors/stitch.py` — 정수-seq 이름목록 시트를 2차 이름소스로
`_stitch_seq` seqmap 조립을 2-pass로:
1. 기존대로 `seq_list/seq_tree/seq_leaf` 가 계층 이름 정의(우선).
2. **`role=='leaf' && has_seq`** 시트(공종목록 등)를 추가 이름소스로 — `setdefault`로 **미정의
   prefix(대분류 자리)만** 채움. 세부/트리 이름은 불변, **대분류만 복원**. 금액은 뒤의 whole-sheet
   roll-up이 정리 → **총액 Δ=0**.

### (B) `src/web/templates/submissions/_link_canvas.html` — leaf-aware 열 라벨 (`c9c78ce`)
그 depth의 노드가 **전부 잎이면 '품명'**, 아니면 분류레벨명(`colHeaderLabel`+`leafOnlyByDepth`).

**결과(실파일 auto, 실 LKC 렌더):** 트리 `컴퓨팅 인프라 > GPU 컴퓨팅 - GPU 서버 노드 > GPU Server`,
열 헤더 **`대분류 | 중분류 | 품명`**, GPU Server `is_leaf=True`. 총액 1,611,071,000 · 13건.

## 7. 결론

**"품목이 소분류" = 두 결함의 합.** (A) 대분류(공종)가 seqmap 이름소스 누락으로 트리에서 소실
→ 트리가 얕아지며 품목 잎이 소분류 depth로 밀림. (B) 그 잎 열이 depth 위치매핑상 '소분류'로 오라벨.
품목의 **구조상 잎 판정(`is_leaf`)은 처음부터 정상**이었고, 하단 라인아이템 표가 품명으로 맞게 나온 것도
그 때문. 두 수정으로 **대분류(공종) > 중분류(산출) > 품명(품목 잎)** 으로 정상화(총액 Δ=0).
