# QDBT — C(데이터 모델) 진행 결정 메모 (밤샘 작업 · 아침 리뷰용)

> 지시: "남은 C 작업을 스스로 판단해 좋은 방향으로 진행하고, 선택 근거를 정리하라. 아침에 리뷰."
> 판단 기준: **밤사이 피드백 없이 앱을 깨뜨리지 않는 것**을 최우선. 되돌리기 쉬운 additive 변경은 구현·테스트까지,
> 핵심 데이터 모델을 바꾸는 구조 변경은 근거와 함께 **설계 제안으로 유보**했습니다.

---

## 1. 오늘 밤 실제로 구현한 것 (테스트 완료)

### A·B (앞서 합의) — 모두 구현·검증
- **시트 매핑 보존(근본)**: 시트 전환 시 현재 시트 매핑을 서버 드래프트로 자동 저장(`/map/save-sheet`), 재진입·통합추출이 그대로 사용. → 버그 1.A~D 해소. (재진입 복원·통합추출 저장매핑 사용 헤드리스 검증)
- **subtotal 제외 현재 시트 한정**: 소계 감지가 반드시 현재 시트 매핑으로만 판단하도록 수정. (버그 2)
- **UX**: 시트 선택칸 상시 표시, 비교단위 트리 **가지(분류) 삭제**, "또는 수동" 혼란 문구 제거·정리.
- (별도) **분류 '자재' 오염 버그** 수정(드래그 이동 시 category 덮어쓰기 → 신규 클러스터 생성 시에만 적용).

### 개선 5 — **메이커(제조사) 필드** ✅ 구현
- 근거: 요청 항목이며 **additive**(기존 모델을 바꾸지 않고 컬럼·역할만 추가)라 밤샘 리스크가 낮음.
- 구현: `submission_items.maker` 컬럼(idempotent 마이그레이션) + 열매핑 역할 "메이커" + 헤더 자동인식(메이커/제조사/브랜드/maker/mfr…) + 추출·스티칭 통과 + 상세 트리에 🏷 표시.
- 검증: 메이커 열 샘플 추출→저장(Arista/Cisco)→트리 표시까지 확인. 앱 124 라우트 정상.

## 2. 유보한 것 + 권장 설계 (아침에 결정 요청)

구조를 바꾸는 항목은 **잘못 구현하면 amount=단가×수량 불변식·비교·카탈로그 전반에 파급**되어, 피드백 없이 밤에 밀어붙이면 위험이 큽니다. 그래서 구현 대신 설계안을 정리했습니다.

### 개선 4 — **부품 레벨 신설** ✅ **구현 완료(2차)**
- 열매핑 역할 "부품" 추가. 부품 열이 있으면 `대>중>소>세>품목` 경로에 **부품을 잎**으로(품목당 N개),
  없으면 품목이 잎. 단일추출(`extract_by_mapping`)·통합추출(`stitch`) 양쪽 반영. 세분류=품목 중복 방지 가드.
  헤더 자동인식(부품/부속/구성품/part/component). 스키마 무변경. — 헤드리스 검증 완료.
- (원 설계안 아래 보존)
- **권장안(스키마 무변경, cat5 재사용)**: 추출 시 "부품" 역할을 두고, 그 열이 매핑되면
  **품목을 분류 경로의 한 단계(cat5)로 내리고, 부품을 잎(name)** 으로 삼는다.
  - 부품 있음 → path=`…>세>품목`, 잎 이름=부품 (한 품목에 여러 부품 = 여러 잎).
  - 부품 없음 → 잎 이름=품목 (현재와 동일).
- 장점: 스키마·불변식 무변경. path 문자열만 깊어짐 → 스티칭·트리·비교가 그대로 동작.
- 유의: 추출 경로가 둘(단일 `extract_by_mapping`, 다중 `stitch`)이라 양쪽에 동일 규칙을 넣어야 함. 그래서 **테스트 세트를 먼저 만들고** 구현 권장(반나절 규모).

### 개선 6 — **레벨별 단가 = 하위 잎 amount 합(roll-up)** ✅ **결정·성립 확인(2차)**
- **결정(사용자)**: 레벨의 "단가"는 그 하위 잎들의 **amount(=단가×수량) 합**. 예) 노트북(품목) 단가 = 램 amount(램단가×2)+SSD amount. "램 1개 단가"가 아니라 "램 2개 값"이 구성요소.
- **결과**: 이는 기존 소계 roll-up과 동일 → **별도 저장(node_attr) 불필요**. 부품 구현 + 기존 `build_items_tree` 노드금액/`group_items_by_level`이 이미 이 의미로 동작.
- 검증: 노트북=500,000=램200,000(=100,000×2)+SSD300,000, 각 레벨 하위합산 정확. 트리에 "레벨별 단가 = 금액(하위 잎 합산)" 라벨.
- 남는 부분: **규격·메이커의 레벨(가지) 표기**는 비합산 속성이라 별도 처리 필요 시 아래 원안(node_attr) 참조. 잎(품목/부품)의 규격·메이커는 이미 저장·표시됨.

#### (원안 보존) 단가가 '독립 입력'이었을 경우 — 별도 속성 테이블
- 현재는 이 값들이 **잎(품목) 전용 필드**. 이를 "모든 노드가 가질 수 있는 속성"으로 일반화하는 요구.
- **권장안: 별도 속성 테이블** `node_attr(submission_id, node_path, level, attr, value)` 신설.
  - 잎의 단가/수량/금액 불변식은 `submission_items`에 **그대로 유지**(합계 신뢰성 보존),
    분류·품목·부품 노드의 부가 속성(규격·메이커·참고단가)만 `node_attr`로 붙인다.
  - 이유: `submission_items`를 계속 넓히면 잎 전용 불변식과 노드 속성이 섞여 합계·환율 로직이 취약해짐.
    노드 속성을 분리하면 표시·비교에서 레벨별 속성을 자유롭게 조회하면서 핵심 금액 로직은 불변.
- **리뷰 포인트**: (a) 레벨별 "단가"가 잎 합계와 어떤 관계인지(표시용 참고값 vs 합산 대상?) —
  이걸 정해야 비교·카탈로그 반영 방식이 결정됨. 이 결정이 6번의 핵심이라 임의로 정하지 않았습니다.

### 개선 8 — **"외 10종" 요약 항목 처리**
- 상위 트리 시트에서 하위가 "○○ 외 10종"으로 묶여 기술되는 경우.
- **권장안(비파괴 우선)**: ① `외\s*\d+\s*(종|개|점)` 정규식으로 **요약 노드 탐지 → residual로 표시**
  ("요약 항목 — 세부 시트로 대체 필요"). ② 세부 시트에 해당 하위가 있으면 **"정보 많은 쪽으로 대체"를 사용자 확인 후** 수행(자동 덮어쓰기는 기본 off). 파괴적 병합을 밤에 자동화하지 않기 위함.

### 개선 9 — **비교단위/스티칭 대상 수동 연결**
- 대부분 이미 커버됨: residual **경로 재지정(reassign-path)** + 비교화면 **클러스터 병합/이동**.
- A(매핑 보존) 수정으로 "분류가 잘못돼 스티칭 대상이 각각 보이는" 상당수가 사라질 것으로 예상.
- 남는 gap이 있으면 그때 "스티칭 노드 잇기" 전용 UI를 최소로 추가 권장(지금은 중복 UI 신설 보류).

---

## 3. 권장 진행 순서 (아침 결정 후)
1. **개선 4(부품)** — 테스트 세트 → `extract_by_mapping`·`stitch` 양쪽 구현. (스키마 무변경, 리스크 중하)
2. **개선 6** — 위 "리뷰 포인트(레벨별 단가의 의미)" 확정 후 `node_attr` 도입. (리스크 상, 결정 선행)
3. **개선 8** — 탐지+비파괴 대체(확인형). (리스크 중)
4. **개선 9** — gap 확인 후 최소 추가. (리스크 하)

## 4. 이번 패치 포함/미포함
- 포함: A·B 전부 + 분류오염 수정 + **메이커(5)**. 스키마 마이그레이션 1건(`maker`) — 재기동 시 자동 적용.
- 미포함(설계 유보): 부품(4)·레벨별 속성(6)·외N종(8)·수동연결(9).
