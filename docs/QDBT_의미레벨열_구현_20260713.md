## (1) 구현 — 의미 레벨 열 그리드

### (a) 항목·노드에 의미 레벨 부여 (구조 불변)
- `extract_by_mapping`(cat 모드)·`stitch._stitch_passthrough`가 각 path 세그먼트의 **절대 분류레벨**
  (대=1·중=2·소=3·세=4)과 잎 레벨(품명=5·부품=6)을 산출.
- `submission_items.cat_levels`(JSON `{"segs":[...],"leaf":N}`, nullable, 자동 마이그레이션)에 저장.
- `build_items_tree`가 각 노드에 `level` 부여. **없으면 depth 폴백**(seq/band·구데이터 → 기존 배치 유지).
- 금액·경로·depth·건수 불변.

### (b) 캔버스 = 의미 레벨 고정 열 그리드
- `_link_canvas.html`: 노드를 트리 depth가 아니라 `col = level-1` 열에 배치. 최대 레벨까지 **빈 중간
  열도 렌더**. 부모→자식 SVG 연결선은 좌표 기반이라 **빈 열을 가로질러** 그려진다(목업).

### 스냅샷 (서버리스 DOM 렌더, `tests/rob/canvas_grid.js`)

순수 `[대,품명]` (직접 붙임):
```
col0 [대분류]: ['재료비']
col1 [중분류]: []          ← 빈 열(보임)
col2 [소분류]: []          ← 빈 열
col3 [세분류]: []          ← 빈 열
col4 [품명]  : ['납블록']   ← 잎은 품명 열, 재료비→납블록 연결선이 중/소/세 가로지름
```

얕은·깊은 공존:
```
col0 [대분류]: ['재료비']
col1 [중분류]: ['기구부']
col2 [소분류]: ['차폐부']
col3 [세분류]: ['납계열']
col4 [품명]  : ['납블록','볼트']   ← 얕은 잎·깊은 잎 모두 품명 열
```

seq 폴백(C3 실파일): `대분류 | 중분류 | 품명` (depth 폴백 → 기존과 동일, 회귀 없음).

## (2) 설계안(확인 요청) — 그리드에서 '아래로 드래그' 재레벨링

사용자 요청: "다중시트 연계에서 **최하 단위 묶음이 중/소/세분류에 있는 경우**, 그리드에서 **아래로
드래그-드랍으로 조정**." → 레벨 열 그리드에서 **묶음(가지)을 더 하위 레벨 열로 드래그해 레벨을 조정**.

기존 `bulk-reparent`(부모 바꾸기)와 **다른 축**: 부모는 그대로 두고 **의미 레벨(열)만** 바꾸는 것으로
해석. 시맨틱이 애매해 **아래 3안 중 확인 후 구현**하려 합니다(미구현).

### 안 A — 레벨만 내림(표시 재레벨링) *(권장)*
- 드래그한 가지(및 하위 서브트리)의 `cat_levels`를 대상 열 레벨로 **평행 이동**(예 소=3 → 세=4).
- **비파괴·Δ=0**: `cat_levels`(표시 메타)만 갱신, path·금액·부모 불변. 되돌리기 가능.
- 장점: 목업의 "열 위치 조정"에 가장 부합, 안전. 단점: 트리 부모관계와 레벨이 어긋날 수 있음(표시상).

### 안 B — 특정 하위 노드에 편입(reparent)
- 기존 bulk-reparent 재사용(부모를 대상 하위로). path·depth 바뀜(총액 Δ=0).
- 장점: 실제 구조 이동. 단점: 사용자가 말한 '레벨 조정'과 다름(부모가 바뀜).

### 안 C — 비교 단위(compare unit) 지정
- 그 레벨을 '기능단위 비교' 기준으로 지정(기존 compare_units). 레벨 표시와 별개 개념.

### 확인 필요
1. 의도가 **안 A(레벨만 조정, 부모 유지)** 가 맞는지?
2. 드래그 방향 제약: **아래(더 하위 레벨)로만** vs 양방향? 순환/역전 방지 규칙?
3. 서브트리 동반: 가지를 내리면 **하위도 같이 상대 이동** vs 그 가지만?

→ 위 확인되면 미니 목업(그리드 드래그 전/후) + 작은 커밋으로 구현하겠습니다. 비파괴·Δ=0·순환 방지 준수.
