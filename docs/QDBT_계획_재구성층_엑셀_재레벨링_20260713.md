## #2 — 신규 분류 at any level (사용자 재구성층, 비파괴 오버레이)

### 목표
대분류뿐 아니라 중/소/세 **어느 레벨에서도** 사용자가 '신규 분류'를 만들고, 항목/묶음을 그 아래로
이동. **견적 원본 연계와 별개의 재구성층** — 정본 불변, 오버레이로 저장.

### 현황
- `register-standard-category`는 **도메인 표준(catalog_categories)** 에 대분류만 추가(공유 기준정보).
- `tree/reparent-branch`·`link/node`는 **submission_items.path 를 직접 변경**(오버레이 아님).
- `map_config`에 `link_overrides`(수기 미연계 플래그)·`sheet_selection` 등 이미 제출서별 오버레이 저장 중.

### 제안 (저장 위치·구조)
- **`map_config.recon`(재구성 오버레이, 제출서별·비파괴)**:
  ```json
  {"recon": {
     "nodes": [{"id":"u1","name":"신규중분류","level":2,"parent_path":"재료비"}],
     "moves": {"<item_id>": "재료비 > 신규중분류"}   // 항목→오버레이 경로 재지정
  }}
  ```
- **트리 조립**: `build_items_tree`가 `recon.moves[item_id]`가 있으면 그 경로를, 없으면 정본 path를 사용
  (오버레이 우선). `recon.nodes`로 신규 분류 노드 삽입(level 지정). **submission_items.path 불변.**
- **신규 분류 노드 레벨**: 사용자가 만든 레벨(2/3/4…) 그대로 `level` 부여 → 캔버스 의미열에 배치.
- **비교/클러스터링 관계**: 재구성층은 **표시·집계 트리**에만 영향. 카탈로그 매칭(item_match)·클러스터
  (catalog_clusters)는 **item_id 기준이라 무영향**(경로가 바뀌어도 item은 그대로) → 3단계 원칙 유지.
  단, '기능단위 비교(compare_units)'를 재구성 경로로 잡고 싶으면 compare_units를 오버레이 경로로
  지정하는 별도 옵션 필요(2차).
- 라우트(신규): `POST /<sid>/recon/node`(신규 분류 생성), `POST /<sid>/recon/move`(항목/묶음 이동),
  `POST /<sid>/recon/reset`. 총액 Δ=0(경로만).

### 확인 필요
1. 저장을 **`map_config.recon` 오버레이**(정본 path 불변)로 — 맞는지? (현재 reparent는 path 직접 변경
   → 이와 **이원화**: '연계(정본 path)' vs '재구성(오버레이)'. 아니면 재구성도 path 직접 변경으로 통일?)
2. 비교/클러스터링은 **item_id 기준 무영향**으로 두고, 재구성 경로 비교는 2차 옵션으로 미룰지?

## #3 — 레벨별 캔버스 엑셀 추출 (형식 계획)

### 목표
확정/연계된 레벨 트리를 엑셀로: **열 = 대분류·중분류·소분류·세분류·품명 + 규격·수량·단가·금액**,
빈 레벨은 빈 칸, 잎=품명 행.

### 형식 (한 잎 = 한 행)
| 대분류 | 중분류 | 소분류 | 세분류 | 품명 | 규격 | 수량 | 단위 | 단가 | 금액 |
|---|---|---|---|---|---|---|---|---|---|
| 재료비 | | | | 납블록 | 순납 | 150 | EA | 64000 | 9,600,000 |
| 컴퓨팅 인프라 | GPU 컴퓨팅 | | | GPU Server | H100x8 | 8 | 대 | 81,574,000 | 652,592,000 |

- 각 잎의 **경로 세그먼트를 자기 의미레벨 열**(node.level/cat_levels)에 배치, 빈 레벨 열은 공백.
  잎(품목)은 **품명 열**. seq/band(레벨 폴백)는 depth 순서로 채움.
- 상위 분류 셀은 **연속 잎에서 반복 생략(병합 느낌)** 옵션(기본: 첫 잎만 표기).

### 재사용
- `reports/excel_report.py`(openpyxl 스타일 `_h`/`_d` 헤더·서식) 재사용. 데이터는
  `build_items_tree`(node.level 포함) 잎 순회 → 열 배치. 신규 함수
  `export_level_tree_xlsx(submission_id) -> Path` + 라우트 `GET /<sid>/export/level-tree.xlsx`.
- 총액 검증행(합계) 부가. 금액 Δ=0(추출 값 그대로).

### 확인 필요
1. 상위 분류 셀 **반복 생략(병합)** vs **매 행 반복** 중 기본값?
2. 최대 레벨 열은 **고정 5(대~품명)** vs 데이터 최대 레벨까지 가변? (부품 있으면 +부품 열)

## #4 — 드래그 재레벨링 (안 A 확정: 레벨만·부모 유지·양방향·서브트리 동반·순환 방지)

### 미니 목업 (전 → 후)

전: '경비'(소분류)를 세분류 열로 아래 드래그
```
대분류    중분류    소분류    세분류    품명
공사비     ┌ 관리비   ┌ 경비 ───────────────▶ (드래그)
           └ ...      └ 유류비(경비의 자식)
```
후: 경비=세분류로 내림(부모 '관리비' 유지), 자식 유류비도 +1 동반 → 품명 쪽으로
```
대분류    중분류    소분류    세분류    품명
공사비     관리비              경비
                               (빈 소분류)   유류비
           └ 연결선: 관리비 → 경비(세분류) → 유류비(품명), 빈 열 가로지름
```

### 시맨틱 (확정 반영)
- **레벨만 조정**(부모 path 불변) — `cat_levels`/`level` 오버레이만 변경(비파괴·Δ=0).
- **양방향**: 상위/하위 레벨 열 어디로든. **서브트리 동반**: 드래그 노드의 하위도 같은 delta 만큼 이동.
- **순환/역전 방지**: 새 레벨은 **부모 레벨 < 새 레벨** 유지(부모보다 위로 못 감). 하위는 delta 적용
  후에도 **엄격 증가**(자식 레벨 > 부모 레벨) 유지. 품명(5)·부품(6) 경계 클램프.
- 저장: `map_config.recon.level_overrides = {"<path>": <newLevel>}` (또는 #2의 recon과 통합). 정본 불변.
- 캔버스: 드롭 시 대상 열의 레벨로 delta 계산 → 서브트리 level 갱신 → 재렌더(연결선 자동).

1. `map_config.recon`(#2)과 **통합 저장**할지(레벨·이동·신규노드를 한 오버레이로)?
2. 델타 이동 시 하위가 품명(5)을 넘으면(부품 6 초과) **클램프** vs **금지(드롭 불가)**?
