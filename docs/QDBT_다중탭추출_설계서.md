# QDBT — 엑셀 다중 탭 통합 추출 설계서

> 대상 버전: v0.9.8 (예정) · 작성 기준: v0.9.7 코드
> 상태: 설계 확정, 구현 착수 전
> 핵심: 한 업체 견적이 여러 탭으로 나뉜 엑셀을, **탭별 매핑을 지정해 하나의 제출서로 통합 추출**

---

## 1. 요건 정의

### 1.1 배경

한 업체가 견적을 여러 탭(시트)으로 나눠 제출하는 경우가 있다. 이를 **합쳐서 하나의 제출서(submission)로** 다뤄야 소계·비교·클러스터링이 전체 기준으로 이뤄진다.

- **의미**: 여러 탭 = 한 업체 견적의 분할 → 하나의 제출서로 통합
- **구조**: 탭마다 열 구조가 다를 수 있음(섞임) → 탭별 독립 매핑 필요
- **탭 유형 혼재**: 어떤 탭은 자체 분류 체계를 가지고(분류기반), 어떤 탭은 품목(잎)만 나열됨(세부항목)

### 1.2 확정된 설계 결정

| 항목 | 결정 |
|------|------|
| 통합 단위 | 여러 탭 → **하나의 제출서**로 병합 |
| 매핑 방식 | **탭별 독립 매핑**(접근 A, 시트별 순차) |
| 탭 유형 | **분류기반** / **세부항목** 두 유형을 탭별로 지정 |
| 세부항목 탭 배치 | 사용자가 **상위 분류 경로를 탭별로 지정** |
| 추출 흐름 | 탭별 매핑 저장 → 마지막에 **일괄 통합 추출** |
| 합계 | `recompute_subtotal`이 전체 잎 합산 → 자동 정합 |

### 1.3 탭 유형별 통합 규칙

- **분류기반 탭**: 탭 내부에 대분류·중분류·품목이 온전. 내부 트리를 **그대로 편입**.
- **세부항목 탭**: 상위 분류 없이 품목만 나열. 사용자가 지정한 **배치 경로 아래에 배치**.
  - 예: "GPU 서버·스토리지"만 있는 탭 → 지정 경로 "자재 › 서버 장비" 아래로 편입

## 2. 현재 구조의 제약 (확장 대상)

코드 확인 결과, 현재는 **단일 시트 전제**로 설계되어 다음 세 지점을 확장해야 한다.

### 2.1 매핑 저장 — 단일 시트만
- `submissions.map_config`에 시트 하나의 매핑만 저장: `{sheet, mapping, header_row, compare_units, excluded_rows, nego_rows}`
- **확장**: 시트별 매핑 딕셔너리로 — `{sheets: {시트명: {mapping, header_row, tab_type, mount_path, ...}}, ...}`

### 2.2 추출 병합 — 매번 삭제 후 교체
- `column_map_extract`가 `delete_submission_items(submission_id, keep_nego=True)`로 **기존 항목 삭제 후 새로 넣음**(823행). → 여러 탭 누적 불가.
- **확장**: 통합 추출 시 한 번만 삭제하고, 모든 탭 항목을 **누적 삽입**. 또는 시트별 추출을 메모리에 모아 마지막에 일괄 저장.

### 2.3 시트 기록 — 단일 시트만
- `extracted_sheets`에 `[sheet]` 하나만 기록.
- **확장**: 추출한 모든 시트 목록 기록.

## 3. 데이터 모델 설계

### 3.1 map_config 구조 확장 (하위 호환)

```json
{
  "version": 2,
  "sheets": {
    "자재": {
      "mapping": {"2":"spec","4":"qty",...},
      "header_row": 4,
      "tab_type": "category",        // 분류기반
      "mount_path": null,
      "compare_units": [...],
      "excluded_rows": [...], "nego_rows": [...]
    },
    "추가장비": {
      "mapping": {...}, "header_row": 2,
      "tab_type": "leaf",            // 세부항목
      "mount_path": "자재 > 서버 장비",  // 배치 경로
      "compare_units": [...]
    }
  }
}
```
- `version: 2`로 구분. 기존 단일 매핑(version 없음)은 그대로 읽어 1개 시트로 취급(하위 호환).
- `tab_type`: `"category"`(분류기반) | `"leaf"`(세부항목)
- `mount_path`: 세부항목 탭의 배치 경로. 분류기반은 null.

### 3.2 스키마 영향
- **없음**. `map_config`(TEXT)·`extracted_sheets`(TEXT) 기존 컬럼에 JSON 구조만 확장. 마이그레이션 불필요.

## 4. 통합 추출 로직

### 4.1 흐름

```
[열 매핑 화면] 탭 전환하며 각 탭 지정
   탭A(자재): 매핑 + 유형=분류기반 → 저장
   탭B(추가장비): 매핑 + 유형=세부항목 + 배치경로="자재>서버장비" → 저장
   ...
        │  모든 대상 탭 지정 완료
        ▼
[통합 추출 실행] "선택 탭 통합 추출"
   for 각 시트 in map_config.sheets:
       items = extract_by_mapping(파일, 시트, 매핑, 헤더행, ...)
       if tab_type == "leaf":
           items = 각 item.path 앞에 mount_path 접두  // 배치 경로 아래로
       all_items += items
   delete_submission_items(sid, keep_nego=True)   // 한 번만
   insert_items_bulk(sid, all_items)              // 전체 누적
   recompute_subtotal(sid)                        // 전체 합산
```

### 4.2 세부항목 탭의 경로 접두

세부항목 탭의 각 item은 상위 분류가 없으므로, `mount_path`를 경로 앞에 붙여 트리에 편입한다.
- 원본 item: `path="", name="GPU 가속 서버"`
- 배치 후: `path="자재 > 서버 장비", name="GPU 가속 서버"`
- → 분류기반 탭의 항목과 같은 트리 레벨에서 만난다 (잎 완전경로 정합)

### 4.3 합계 정합
- 모든 탭 항목이 한 제출서에 누적 → `recompute_subtotal`이 전체 잎 합산 → 소계 자동 정합.
- 특별 네고·통화는 탭 무관하게 항목 단위로 이미 처리됨(기존 로직 재사용).

## 5. UI 설계 (열 매핑 화면 확장)

### 5.1 탭 선택·상태 표시
- 현재: `?sheet=` 단일 전환 드롭다운
- 확장: 시트 목록에 **지정 완료 표시**(✓)와 **탭 유형 배지**(분류/세부). 대상 시트 **다중 선택**(체크).

### 5.2 탭별 지정 패널
- 각 탭 진입 시: 열 매핑(기존) + **탭 유형 선택**(분류기반/세부항목) + (세부항목이면) **배치 경로 선택**.
- "이 탭 지정 저장" → map_config.sheets에 누적.

### 5.3 통합 추출 버튼
- 모든 대상 탭 지정 후 "선택 탭 통합 추출(N개)" 활성화 → 4.1 흐름 실행.

## 6. 구현 단계

**1단계 — 매핑 저장 확장**: map_config를 version 2(시트별 딕셔너리)로. 하위 호환 읽기. 화면에 탭 유형·배치경로 입력 추가, 시트별 저장 라우트.

**2단계 — 통합 추출 라우트**: 시트별 매핑 순회 → extract_by_mapping 반복 → 세부항목 탭 경로 접두 → 누적 삽입 → recompute. 단일 시트 추출과 별도 엔드포인트 또는 통합.

**3단계 — UI 완성**: 탭 상태 표시(지정완료·유형), 다중 선택, 통합 추출 버튼, 진행 피드백.

**4단계 — 검증·정합**: 합계 불변식(Σ탭 == 제출서), 세부항목 배치 정확성, 하위 호환(기존 단일 시트 견적 정상), 도메인 분류 정합.

---

## 7. 검증 기준

- **합계 불변식**: 통합 추출 후 `제출서 소계 == Σ(모든 탭 잎 금액)`
- **세부항목 배치**: leaf 탭 항목이 지정 mount_path 아래에 정확히 편입, 분류기반 탭과 같은 트리에서 정합
- **하위 호환**: 기존 단일 시트 견적서 재추출·재진입 정상 (version 없는 map_config)
- **탭 유형 혼재**: 분류기반 + 세부항목 탭이 한 제출서에 올바로 통합
- **누적 정확성**: 여러 탭 추출 시 이전 탭 항목이 삭제되지 않고 누적(수기 nego 보존)

- 배치 경로(mount_path) 지정을 기존 분류 선택으로 제한할지, 자유 입력 허용할지

# 부록 A — 트리·세부 분리 구조 (골격/살 분리)

> 다중 탭의 특수·고난도 케이스. 트리(구조)와 내역(데이터)이 다른 탭에 분리된 견적서.
> 확정 요건: 자동(탭명)+수동 하이브리드 연결 · 트리 탭에 노드별 소계 존재 · 세부 탭 1:N 노드 · 노드 구분 방식 혼재 · 소계로 배치·누락 자동 검증

## A.1 구조 정의

| 탭 유형 | 내용 | 역할 |
|---------|------|------|
| **트리 탭** | 대·중·소분류 계층 + 노드별 소계 금액 (품목 없음) | 구조 정의 + 검증 기준선 |
| **세부 탭(다수)** | 실제 품목·수량·단가·금액 | 데이터(잎). 트리의 여러 노드로 흩어져 배치 |

기존 탭 유형(category/leaf)에 **structure(구조/트리)** 유형을 추가한다. 총 3유형:
`category`(분류기반·자체완결) · `leaf`(세부항목·단일 배치) · `structure`(트리·구조정의).

## A.2 핵심 난제 — 세부 탭 1:N 노드 배치

세부 탭 하나가 트리의 **여러 노드**를 포함(1:N)한다. 따라서 "탭 전체를 노드 하나에 매단다"가 불성립. 세부 탭 **내부의 각 항목이 어느 노드에 속하는지** 판별해야 한다.

### 노드 구분 방식 (탭마다 혼재)

세부 탭 내부의 노드 구분 단서가 탭마다 다르므로, 탭별로 판별 방식을 지정한다.

1. **구분 행(소분류 헤더)**: 세부 탭이 "1. 서버 장비" 구분 행으로 섹션이 나뉨 → 구분 행을 트리 노드명과 매칭. (기존 `is_category_header` 인식 재사용)
2. **분류 열**: 각 품목 행에 소속 분류 열 존재 → 열 매핑에서 cat1~cat5로 지정. (기존 `CAT_ROLES` 재사용)
3. **평평한 나열**: 명시적 구분 없음 → 소계 금액 대조·품명 유사도로 추론, 수동 보정 의존.

→ 방식 1·2는 **기존 추출기 기반이 이미 지원**(cat1~cat5 열, is_category_header 소계 인식). 방식 3만 수동 개입 필요.

## A.3 연결 전략 — 자동(탭명/구분) + 수동 보완

```
[1단계] 트리 탭 추출 → 노드 트리 + 노드별 소계 확보 (구조 정의 소스)
        예: 자재 > 서버 장비(소계 604,200,000) / 네트워크(소계 …) …
        │
[2단계] 세부 탭별 항목 추출 + 노드 귀속 판별
        · 구분 행/분류 열 → 트리 노드명과 자동 매칭 (영한·별칭·표기편차 흡수)
        · 매칭 실패 항목 → 수동 지정 대기
        │
[3단계] 노드 소계 검증 (배치·누락 자동 검증)
        각 트리 노드: Σ(배치된 세부 항목) == 트리 탭 노드 소계 ?
        · 일치 → 연결 정확 확정
        · 불일치 → 배치 오류/누락 포착 → 해당 노드 수동 보정 유도
        │
[4단계] 통합: 트리 골격 + 배치된 세부 잎 → 하나의 제출서
        recompute_subtotal이 전체 합산 → 소계 자동 정합
```

## A.4 노드 소계 검증 (핵심 안전장치)

트리 탭의 노드별 소계가 1:N 배치의 정확성을 **객관적으로 증명**한다.

```
for 각 트리 노드 N (소계 있는):
    배치합 = Σ(N에 귀속된 세부 항목 amount)
    if 배치합 == N.소계:   ✅ 배치 정확·누락 없음
    else:                  ⚠️ 차액 = N.소계 - 배치합
                           → 누락(차액>0) 또는 오배치(차액<0) 신호
                           → 해당 노드 세부 항목 수동 재배치 유도
```
- 시스템 기존 원칙(공급가액=트리=라인 합계)의 확장.
- 전체 합계뿐 아니라 **노드 단위**로 검증하므로 오류 위치가 특정됨.

## A.5 데이터 모델 (map_config v2 확장)

```json
{
  "version": 2,
  "structure_sheet": "산출내역",        // 트리 탭 지정 (신규)
  "sheets": {
    "산출내역": { "tab_type": "structure",
                  "mapping": {..분류열·소계열..}, "header_row": 3 },
    "서버내역": { "tab_type": "leaf_multi",     // 1:N 세부 탭 (신규)
                  "mapping": {..}, "node_key": "header",  // 구분행 기준
                  "header_row": 2 },
    "인력내역": { "tab_type": "leaf_multi",
                  "mapping": {..cat 열 포함..}, "node_key": "column" }  // 분류열 기준
  }
}
```
- `tab_type`에 `structure`(트리)·`leaf_multi`(1:N 세부) 추가.
- `node_key`: 세부 탭의 노드 구분 방식 — `header`(구분행)·`column`(분류열)·`manual`(수동).
- 스키마 변경 없음(map_config TEXT JSON 확장).

## A.6 UI 흐름

1. 트리 탭 지정: 유형=structure, 분류 계층·소계 열 매핑 → 트리 미리보기.
2. 세부 탭별 지정: 유형=leaf_multi, 노드 구분 방식(구분행/분류열/수동) 선택, 열 매핑.
3. 통합 추출 실행: 자동 매칭 → **노드 소계 검증 리포트**(노드별 일치/차액 표시) → 불일치 노드 수동 보정 → 확정.
4. 결과: 트리 골격 + 세부 잎이 하나의 제출서로 통합.

## A.7 구현 단계 (기존 4단계에 추가)

- **5단계 — 트리 탭 파싱**: structure 탭에서 노드 계층 + 노드별 소계 추출(품목 아닌 구조).
- **6단계 — 1:N 노드 귀속**: 세부 탭 항목을 node_key 방식으로 트리 노드에 매핑(구분행/분류열 자동, 실패분 수동).
- **7단계 — 노드 소계 검증 리포트**: 노드별 배치합 vs 소계 대조 화면, 불일치 보정 UI.

## A.8 검증 기준 (추가)

- **노드 소계 정합**: 모든 소계 보유 노드에서 `Σ배치 == 노드소계` (또는 차액 명시·보정)
- **1:N 배치**: 한 세부 탭 항목이 트리의 올바른 여러 노드로 분산 배치
- **탭명/구분 자동 매칭**: 표기 편차(번호 접두·공백·영한) 흡수
- **수동 보완 경로**: 자동 매칭 실패 항목의 수동 재배치 동작
- **하위 호환**: 트리·세부 분리 아닌 기존 견적서(단일/일반 다중탭) 정상

## A.9 미결 사항 (부록)

- 트리 탭 노드명과 세부 탭 구분명의 매칭 강도(정확일치 vs 유사매칭 임계)
- 노드 소계와 배치합의 허용 오차(반올림·부가세 처리 차이) 범위
- 소계 없는 노드의 검증 대체 방법
- structure 탭이 복수인 경우(총괄+부문별 트리) 처리

# 부록 B — 다단(N레벨) 시트 연계 (목록·트리·세부)

> 부록 A(트리·세부 2레벨)의 일반화. 확정 요구: 목록/트리/세부가 **각각 다른 시트**에 있고, 이를 **드래그앤드랍으로 연계**해 하나의 데이터셋으로 통합. 4단계 프로세스(추출→제안→조정·확정→확정데이터)로 진행하며 확정 후 수정(버전) 가능.

## B.1 부록 A와의 차이 (간극)

| 축 | 부록 A | 부록 B (본 확장) |
|----|--------|------------------|
| 레벨 수 | 2 (트리↔세부) | **N** (목록↔트리↔세부, 그 이상) |
| 연계 조작 | 자동(탭명/구분) + 수동 보완 | **드래그앤드랍이 일급 조작** + 자동 제안 |
| 프로세스 | 추출·배치·소계검증 | **4단계**(추출→제안→조정·확정→확정) |
| 확정 후 | (미정) | 수정 가능, **버전 승격** |

→ 부록 A는 2레벨 특수케이스. 부록 B가 일반 모델.

## B.2 시트 레벨 — 순서 무관, 추론 + 수정

각 시트에 **상대적 계층 레벨**을 부여한다. **레벨은 시트의 물리적 순서와 무관하다** — 셋째로 추출한 시트가 최상위일 수 있고, 첫째 시트가 세부일 수 있다.

### 레벨 표현
- 레벨은 고정된 3종(목록/트리/세부)이 아니라 **상대적 계층 번호**(1=최상위, 2, 3, … 클수록 하위). N단계 자유.
- 명칭(목록/트리/세부)은 레벨의 예시일 뿐, 강제 아님.

### 레벨 결정 — 추론 제안 + 사용자 수정 (둘 다)
1. **시스템 추론(제안)**: 시트 내용으로 레벨 추정.
   - 소계만 있고 품목·단가 없음 → 상위 레벨
   - 번호계층(seq) 깊이 (예: "1" vs "1.1" vs "1.1.1")
   - 품목명·수량·단가 존재 → 하위(잎) 레벨
2. **사용자 수정**: 추론된 레벨을 화면에서 조정(드롭다운/드래그로 계층 이동).

→ 시트 순서에 레벨을 고정하지 않음. 순서와 레벨은 독립 축.

## B.3 연계 모델 — 상하 관계로만, 방향 자유

노드 연결은 **레벨의 상하 관계**로만 결정되며, **시트 순서·드래그 방향과 무관**하다.

### 연결 규칙
```
레벨이 다른 두 노드 연결 시:
  · 레벨이 높은(상위, 번호 작은) 쪽 = 부모
  · 레벨이 낮은(하위, 번호 큰) 쪽 = 자식
  · 같은 레벨끼리 = 연결 불가
```
- **방향 자유**: 상위를 하위로 드래그하든, 하위를 상위로 드래그하든, 시스템이 레벨을 보고 부모·자식을 자동 판정.
- **순서 무관**: 어느 시트가 먼저 추출됐는지는 연결에 영향 없음. 나중 시트가 상위 부모일 수 있음.
- **건너뛰기 허용**: 인접 레벨만이 아니라 상하 관계면 연결(레벨 1 노드에 레벨 3 노드 직접 연결 가능). 중간 레벨이 없거나 비어 있어도 상위-하위 직결.

### 조립 결과
- 각 노드가 parent를 가지면 전체가 하나의 트리로 조립.
- 물리 저장: 각 잎의 완전 경로 = (최상위 → … → 잎) path 구성 → 기존 트리 구조에 흡수(스키마 무변경).
- 레벨 간 노드 개수·깊이가 시트마다 달라도, 상하 관계만 성립하면 통합됨.

## B.4 단일·다중 통합 모델 (하나의 흐름)

단일 시트와 다중 시트를 **별개 기능이 아니라 하나의 통합 흐름**으로 다룬다. 단일 시트는 "시트 1개인 특수 케이스"다.

### 통합 흐름
```
1. 시트 추출 (1개 이상)
2. [시트 ≥2] 레벨 지정(추론+수정) + 연계(드래그, 상하관계·방향자유)
   [시트 1개] 레벨·연계 불필요 — 그 시트가 곧 트리
3. 통합 트리 완성 (단일이든 다중이든 결과는 하나의 트리)
4. 비교 단위 지정 (통합 트리의 어느 레벨을 비교 기준으로) ← compare_units
5. 확정 (스냅샷 · 버전)
```

### 기존 compare_units와의 관계
- 기존 단일 시트: 추출 → 트리 → **compare_units로 비교 단위 지정**(4단계).
- 통합 모델: 시트 연계로 만든 트리 위에서 **동일하게 compare_units 지정**.
- → **compare_units는 "통합 트리에서 비교 기준 레벨을 고르는" 공통 단계.** 단일·다중 모두 이 단계를 거친다.
- 단일 시트는 2단계(레벨·연계)를 건너뛸 뿐, 3~5단계는 동일.

### 의의
- 단일 시트 비교단위 트리와 다중 시트 연계가 **같은 파이프라인**. 별도 코드·화면 이원화 없음.
- 시트 수에 따라 2단계(연계)만 조건부 활성. 나머지는 공통.

## B.5 4단계 프로세스 (리뷰·확정 루프와 정합)

부록 B는 앞서 정한 **리뷰·확정 4단계 루프**를 시트 연계에 특화한 것이다.

```
[1 추출]      시트별 레벨 인식 (목록/트리/세부)
    │
[2 정합성 제안]  시스템 자동 연계 (번호·이름·소계 기반)
    │           · 번호계층(seq): "1.1"→"1" 부모 추론
    │           · 이름 매칭: 트리 부모명 ↔ 목록명
    │           · 소계 검증: Σ자식 == 부모 소계
    │
[3 수기 조정·확정] 드래그앤드랍으로 미연계·오연계 보정
    │           · 세부→트리, 트리→목록 드래그
    │           · 실시간 소계 재검증 (연결 시 즉시 정합 확인)
    │           · 전 노드 연계 + 소계 정합 시 확정 가능
    │
[4 확정 데이터]  통합 트리 (목록>트리>세부) + 스냅샷 + 버전 v1
```

- 2단계 자동 제안 = "시스템 제안", 3단계 드래그 = "사람 수정", 소계 검증 = "시스템 리뷰", 확정 = "사람 확정" → **4단계 리뷰·확정 루프와 1:1 대응**.

## B.5 자동 연계 제안 (2단계)

시스템이 세 가지 단서로 부모를 추론:
1. **번호계층(seq)**: 트리 "1.1"의 부모 = 목록 "1". 세부 항목의 번호가 트리 노드 번호로 시작하면 귀속. (가장 강한 신호)
2. **이름 매칭**: 트리 노드의 상위 분류명이 목록명과 일치. (표기 편차 흡수)
3. **소계 대조**: Σ(자식 후보) == 부모 소계이면 연계 확신. (금액 검증)

→ 자동 성공분은 파선(제안)으로, 실패분은 미연계(붉은 표시)로 3단계 드래그 유도.

## B.6 소계 검증 (연계의 안전장치)

각 연결마다 부모-자식 금액 정합을 실시간 확인:
```
목록 노드 총액 == Σ(연결된 트리 노드 소계) ?
트리 노드 소계 == Σ(연결된 세부 항목 금액) ?
```
- 드래그로 연결하는 즉시 재검증 → 오연결이면 차액 경고.
- 전 노드 정합 시에만 확정 허용 → 누락·중복 방지.
- 기존 원칙(공급가액=트리=라인) 을 다단으로 확장.

## B.7 확정 데이터와 수정 (버전)

- 확정 시: 목록>트리>세부가 하나의 트리로 통합, **스냅샷 v1** 저장.
- 수정: 세부(품목·단가) 수정 가능, 트리·분류 구조 유지 원칙. 수정 시 **v2 승격**(부록 C 버전관리).
- 확정 취소 → 편집 복귀(3단계). 연계 재조정 가능.
- item_match 분리로, 확정 후 비교·클러스터링이 원본 트리를 건드리지 않음.

## B.8 데이터 모델 (map_config v3)

```json
{
  "version": 3,
  "sheets": {
    "공종목록": { "level": "list",   "mapping": {..}, "header_row": 2 },
    "내역트리": { "level": "tree",   "mapping": {..seq..}, "header_row": 3 },
    "품목세부": { "level": "detail", "mapping": {..}, "node_key": "seq" }
  },
  "level_order": ["list", "tree", "detail"],
  "links": {                          // 연계 결과(확정 시 스냅샷에 포함)
    "T1": "L1", "T2": "L1", "T3": "L2",
    "D1": "T1", "D2": "T1", "D3": "T2"
  }
}
```
- `level`: 시트 데이터 레벨. `level_order`: 연계 순서.
- `links`: 노드 parent 매핑(드래그 결과). 확정 시 최종 트리 path로 변환.
- 스키마 무변경(map_config JSON 확장).

`QDBT_다중시트연계_목업.html` — 4단계 조작 가능:
- 3열 캔버스(목록·트리·세부), SVG 연결선(자동=파선/수기=실선).
- 미연계 노드를 상위로 드래그 → 실시간 소계 검증 → 확정.

## B.10 구현 단계 (부록 A·다중시트 구현설계 위에)

- **1단계 — 레벨 인식 추출**: 시트별 level 지정(list/tree/detail), 각 레벨 추출.
- **2단계 — 자동 연계 제안**: seq·이름·소계로 parent 추론.
- **3단계 — 드래그 연계 UI + 실시간 검증**: 노드 parent 재지정, 소계 재계산.
- **4단계 — 통합·확정**: links를 트리 path로 변환, 스냅샷 v1.
- 선결: T6(다중 시트 누적 추출), T5(합계 검증 모듈), 리뷰·확정(T11).

## B.11 미결 사항

- 레벨이 4개 이상일 때(목록>대>중>세부) 연결 규칙 일반화
- **[확정] 레벨 건너뛰기 허용**: 레벨 1에 레벨 3 직결 가능(중간 레벨 없거나 비어도). 소계 검증은 존재하는 레벨 간에만 적용.
- 자동 제안 신뢰도 임계(번호 vs 이름 vs 소계 우선순위)
- 소계 허용 오차(부가세·반올림)
- 한 세부가 여러 트리 노드에 걸치는 경우(안분) 허용 여부
- links를 map_config에 두나 item_match처럼 별도 두나(버전 종속성 고려)
