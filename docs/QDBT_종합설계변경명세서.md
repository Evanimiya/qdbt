# QDBT — 종합 설계 변경 명세서

> 작성 기준: v0.9.7 코드 + 본 세션 전체 설계·검증
> 목적: 여러 개별 설계서를 하나로 통합하고, **비판적 DB 검증의 결론으로 이전 설계를 수정**한 최상위 명세.
> 성격: 단순 요약이 아니라 모순을 해소한 정합적 최종안. 이 문서가 이후 구현의 단일 기준.

---

## 0. 설계 여정 요약 (맥락)

본 세션에서 다음이 순차 도출됐다.

1. **통화·환율 명시** (구현·배포) — 업체별 통화·환율을 추출 페이지에 명시, 역산/수동/미확인 구분, 환율 수정 시 원화 재계산.
2. **도메인/분류 통합 수정** (구현·배포) — '공통' 폴백, 입찰 도메인 전파, 개별 항목 분류 이동.
3. **묶음 펼치기(다층 비교)** (설계) — 전략 A(2단계 계층), 잎 보존, 합계 불변식.
4. **다중 탭 통합 추출** (설계) — 탭별 매핑, 트리·세부 분리(1:N 노드 귀속·소계 검증).
5. **진화 아키텍처 로드맵** (설계) — "분리 먼저"를 폐기하고 "기능 먼저, 분리는 조건부"로.
6. **리뷰·확정 프로세스 + 버전 관리** (설계) — 4단계 루프, 스냅샷, 확정 취소.
7. **DB 단위 비판적 검증** — 3개 오류 + 3개 복잡도 위험 발견.

본 명세서는 7의 검증 결과로 3~6을 수정·정합화한다.

## 1. 비판적 검증이 도출한 핵심 변경 (최우선)

DB 검증에서 드러난 문제와, 그것이 강제하는 설계 변경.

### 1.1 [오류·즉시수정] 환율 재계산 금액 불변식 위반

**문제**: `set_submission_fx_rate`가 `new_price`와 `new_amt`를 **독립 round**해, `amount = unit_price × quantity`가 깨진다. (실증: 단가 333.33·수량 3·금액 1000 → 환율 1380 적용 시 new_price×qty=1,379,985 ≠ new_amt=1,380,000, 15원 차이)

**변경**: amount를 독립 환산하지 않고 **단가에서 유도**한다.
```
new_price = round(orig_price × rate)
new_amt   = round(new_price × quantity)   # 독립 계산 폐지, 단가에서 유도
```
- quantity가 없는 항목(묶음·소계)은 `new_amt = round(orig_amt × rate)` 예외 허용.
- 정책: **단가 기준**을 진실로. 소계가 견적서 원금액과 미세하게 달라질 수 있음을 명시(반올림 차이는 라인 단위로 흡수).
- 이미 배포된 코드이므로 **즉시 수정 대상**(구현 로드맵 0순위).

**추가 완화**: unit_price_orig가 없는 항목의 역산 복원(원화÷환율)은 누적 오차 위험 → 추출 시 unit_price_orig를 **항상 보존**하도록 보강(역산 경로 최소화).

### 1.2 [오류·설계치명] item_id 휘발성 — 버전 관리의 선결 과제

**문제**: item_id는 재추출 시마다 새 UUID로 재생성된다(delete 후 insert). 그런데 스냅샷·클러스터·이력이 item_id를 참조하고, FK에 ON DELETE 절이 **없다**(수동 관리). → 확정 후 재추출하면 버전 참조가 붕괴한다.

**변경 (두 축으로 해결)**:

**(A) 스냅샷을 self-contained로** — 스냅샷은 살아있는 item_id를 **참조하지 않고**, 확정 시점의 값 전체를 내부에 담는다. 재추출로 item_id가 바뀌어도 스냅샷은 독립적으로 유효. (부록 C의 snapshot_json을 "참조"가 아니라 "완결된 값 사본"으로 재정의)

**(B) 확정본 동결(freeze)** — `confirmed` 상태에서는 재추출·item_id 변경을 **금지**한다. 재편집하려면 확정 취소(→ draft)를 거친다. 이로써:
- draft: item_id 가변(재추출 가능)
- confirmed: item_id 동결 → 그 버전 생애 동안 클러스터·이력 참조 안정
- 재확정 시 새 버전 = 새 스냅샷

→ 이 두 축으로 "버전 간 참조 정합성"이 성립. **item_id 안정화 없이는 버전 관리가 불가능**하므로, 이는 부록 C 구현의 절대 선결조건.

### 1.3 [오류·경미] 도메인 보정 마이그레이션 상시 실행

**문제**: 입찰 도메인 전파 보정이 조건 무관하게 매 기동 UPDATE 시도.
**변경**: 1회성 보정 플래그(예: schema_meta에 적용 여부 기록) 또는 "불일치 존재 시에만" 선검사 후 실행. 영구 마이그레이션에서 분리.

### 1.4 [복잡도] 스냅샷 이중화 — 이중 진실 규칙 명문화

**문제**: snapshot_json이 submission_items를 복제 → 정규화 위반·정합성 부담.
**변경 (완화)**: 이중화는 불가피(스냅샷의 본질)하나, **진실 규칙**을 명문화:
- `submission_items` = **현재 작업본**(draft의 진실)
- `submission_snapshots` = **확정 시점 진실**(불변)
- `confirmed` 상태에서는 동결로 인해 작업본 == 최신 스냅샷(일관)
- 조회 시: 비교 WS는 스냅샷을, 편집 WS는 작업본을 본다(명확히 분리)

### 1.5 [복잡도] 상태 축 이중화 — done 종속 규칙으로 제약

**문제**: extraction_status × merge_status 조합 폭발(4×3=12, 다수 무효).
**변경 (완화)**: merge_status를 **extraction_status='done'일 때만 유효**로 제약. 유효 조합을 4개로 한정:
```
extraction_status != 'done'  → merge_status = NULL (병합 이전)
extraction_status == 'done'  → merge_status ∈ {draft, review, confirmed}
```
- 단일 규칙으로 조합 폭발 차단. 상태 기계를 명시(§4).
- extraction_status 이름·값은 유지(기존 10곳 코드 영향 최소화).

### 1.6 [복잡도·경미] role 다목적 과부하

**문제**: catalog_cluster_members.role에 representative/duplicate + 신규 leaf 혼재.
**변경**: 현 단계 수용(스키마 무변경 이점). 단 role 값 상수를 코드에 명시·문서화해 의미 혼선 방지. 향후 부담 누적 시 별도 컬럼 검토.

## 2. 통합 데이터 모델 변경 (전체 종합)

본 세션의 모든 스키마 변경을 하나로 정리. **원칙: 기존 스키마 최대 보존, 신규 최소화.**

### 2.1 이미 적용됨 (구현·배포)
| 대상 | 변경 | 상태 |
|------|------|------|
| submissions.fx_rates | 통화별 환율 맵 JSON | 적용 |
| submissions.fx_rate_used | 대표 환율 | 적용 |
| submission_items.fx_rate_used | 항목 적용 환율 | 적용 |
| bids.base_currency | 비교 기준통화(기본 KRW) | 적용 |
| domains '공통' | 미분류·폴백 도메인 seed | 적용 |

### 2.2 신규 (설계, 미적용) — 버전 관리
| 대상 | 변경 | 근거 |
|------|------|------|
| submissions.merge_status | draft/review/confirmed (done 종속) | 부록 B §1.5 |
| submissions.confirm_version | 현재 활성 버전 번호 | 부록 B |
| **submission_snapshots** (신규 테이블) | self-contained 확정 스냅샷 | 부록 C §1.2 |

**submission_snapshots** (수정된 정의 — self-contained):
```
snapshot_id    PK
submission_id  FK
version        INTEGER
snapshot_json  TEXT     -- 확정 시점 전체 값 사본(item_id 참조 아닌 값 자체)
subtotal       REAL
fx_snapshot    TEXT
status         TEXT     -- active | superseded | cancelled
confirmed_at   TIMESTAMP
confirmed_by   TEXT
cancelled_at   TIMESTAMP
cancel_reason  TEXT
```

### 2.3 신규 (설계, 미적용) — 다중 탭·묶음 펼치기
| 대상 | 변경 | 근거 |
|------|------|------|
| submissions.map_config | v2 구조(시트별 매핑 딕셔너리) | 다중탭 설계 |
| submissions.extracted_sheets | 다중 시트 목록 | 다중탭 |
| catalog_cluster_members.role | 'leaf' 값 추가(컬럼 재활용) | 묶음펼치기 |

**스키마 변경 없이 JSON 확장으로 처리**: map_config·extracted_sheets는 기존 TEXT 컬럼의 JSON 구조 확장. role은 기존 컬럼 값 추가. → 신규 테이블은 submission_snapshots 하나뿐.

### 2.4 마이그레이션 정리
- 도메인 보정을 1회성으로 전환(§1.3)
- 신규 컬럼·테이블은 idempotent 마이그레이션으로 추가(기존 패턴 준수)

## 3. 통합 기능 설계 (수정 반영된 최종)

### 3.1 통화·환율 (구현됨 + §1.1 수정)
- 통화별 환율 맵, 역산/수동/미확인 구분, 기준통화 선택 — 유지
- **수정**: 환율 재계산 시 amount = new_price × quantity 유도(§1.1)

### 3.2 묶음 펼치기 (설계 + 버전 정합)
- 전략 A(2단계 계층), 잎 보존(role='leaf'), Σ잎==묶음 검증 — 유지
- **정합**: 잎 매칭은 confirmed 버전에서 수행(동결된 item_id 기준) → 참조 안정

### 3.3 다중 탭 통합 추출 (설계)
- 탭별 매핑(map_config v2), 트리·세부 분리(structure/leaf_multi), 1:N 노드 귀속, 노드 소계 검증 — 유지
- **정합**: 통합 추출은 draft에서만(확정 전). 확정 시 스냅샷 고정.

### 3.4 리뷰·확정 프로세스 (설계 + §1.4·1.5 수정)
- 4단계 루프(시스템 제안→사람 수정→시스템 리뷰→사람 확정) — 유지
- 통합 검증 게이트(합계·노드소계·도메인·통화) — 유지
- **수정**: 상태는 done 종속 merge_status(§1.5). 스냅샷은 self-contained(§1.2·1.4).

### 3.5 확정 스냅샷·취소 (설계 + §1.2 수정)
- 스냅샷 저장(+단독 다운로드), 확정 취소(→draft), 버전 단조증가 — 유지
- **수정**: 스냅샷 self-contained. confirmed 동결로 item_id 안정. 취소 시 스냅샷 cancelled 보존.

## 4. 통합 상태·생명주기 모델 (신규 종합)

모든 상태를 하나의 생명주기로 정합화. **핵심: 단일 규칙(merge_status는 done 종속)으로 조합 폭발 차단.**

```
[추출 파이프라인]                    [병합 생명주기 (done 이후)]
pending → processing → done ──┬──▶ draft ──review──▶ (검증루프) ──confirm──▶ confirmed(vN)
             │                │       ▲                                          │
           failed            └───(재추출: draft에서만)                    cancel │
                                      │                                          ▼
                                      └──────────────── draft (취소, 스냅샷 보존) 
```

### 상태 규칙
- extraction_status='done' 전: merge_status = NULL
- draft: 자유 편집·재추출(item_id 가변). 스냅샷 없음
- review: 4단계 검증 루프. 편집 가능, 재추출 지양
- confirmed(vN): **동결**(item_id 불변, 재추출 금지). 스냅샷 active. 비교 WS 참조 대상
- cancel: confirmed → draft. 스냅샷 cancelled 보존. 비교 무효 신호
- 재확정: draft → confirmed(v N+1). 새 스냅샷 active, 이전 superseded

### 동결(freeze)이 보장하는 것
- confirmed 동안 item_id 불변 → 클러스터·이력·스냅샷 참조 안정(§1.2)
- 편집하려면 반드시 취소 경유 → 무질서한 왕복 방지(결함 6 해결)

## 5. 통합 구현 로드맵 (우선순위·순서)

비판적 검증 결과를 반영한 최종 순서. 위험·의존을 고려해 재배열.

### 0순위 — 즉시 수정 (배포된 버그)
- **환율 불변식 수정**(§1.1): new_amt = new_price × quantity. 이미 배포된 실 버그.
- 도메인 보정 마이그레이션 1회성화(§1.3).

### 1단계 — 파일·모듈 리팩터링 (저위험·즉시이득)
- bid.html(1943줄) 편집 UI 분리, compare 라우트 논리 구획.
- 되먹임 8곳을 명시적 서비스 함수로 수렴 시작(선택).

### 2단계 — 병합 기능 구현 (경계를 실증)
- 우선순위: **다중 탭 통합 → 트리 조립 → 묶음 펼치기** (의존 순).
- 공통 부품 추출(노드-잎 귀속·합계 검증기·드래그앤드랍).
- 이 단계에서 경계가 드러남.

### 3단계 — item_id 안정화 + 리뷰·확정 (버전 관리 기반)
- **선결**: item_id 동결 메커니즘(§1.2 B) — 이것 없이 버전 관리 불가.
- merge_status·submission_snapshots 도입(§2.2, self-contained).
- 4단계 리뷰 루프·통합 검증 게이트.

### 4단계 — 스냅샷·취소·다운로드
- 확정 스냅샷, 취소, 버전 다운로드.
- 비교 무효 신호·재검토 유도.

### (조건부) 5단계 — 물리적 분리
- **선행조건 충족 시에만**(되먹임 인터페이스·확정 상태·필요 증명).
- 리뷰·확정이 경계를 명료화하므로 **분리 필요성 자체가 낮아짐**(대안 가능).

## 6. 핵심 판단 종합

세션 전체를 관통하는 설계 판단을 명문화한다.

1. **분리보다 프로세스**: 물리적 앱 분리(방식 B)는 성급했다. 리뷰·확정 프로세스가 경계를 명료화하므로, 분리 없이도 목적을 달성할 수 있다. 분리는 필요가 증명될 때만.
2. **동결이 정합성의 열쇠**: item_id 휘발성이 버전 관리의 최대 위협. confirmed 동결이 이를 해결하는 동시에 무질서한 왕복도 규율한다.
3. **스냅샷은 self-contained**: 참조가 아니라 값 사본. 재추출·삭제에 영향받지 않는 독립 기록.
4. **불변식 우선**: amount=단가×수량, Σ잎==묶음, Σ배치==노드소계, 공급가액=트리=라인합. 모든 기능이 이 불변식들을 지켜야 하며, 환율 재계산 버그는 그 위반이었다.
5. **복잡도는 규칙으로 통제**: 상태 축·이중 진실의 복잡도를 없앨 수 없다면, 단일 규칙(done 종속, 진실 분리)으로 통제한다.
6. **기존 스키마 최대 보존**: 신규 테이블은 submission_snapshots 하나. 나머지는 JSON 확장·컬럼 재활용.

## 7. 미결 사항 (다음 리뷰·결정 필요)

- 환율 재계산 정책: 단가 기준 확정 시 소계와 견적서 원금액 차이 허용 범위

## 8. 즉시 실행 가능 항목

"만들어" 지시 시 바로 착수 가능한 순서:
1. **환율 불변식 수정**(§1.1) — 배포된 버그, 최우선.

이후는 각 단계 설계 확정·협의를 거쳐 진행. 개별 설계서(묶음펼치기·다중탭·진화아키텍처+부록BC)는 본 명세서의 하위 상세로 유지된다.
