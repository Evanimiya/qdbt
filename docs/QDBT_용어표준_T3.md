# QDBT 용어 표준 (T3, A안 확정 · 2026-07-10)

> 목적: "확정"과 "채택"이 서로 다른 의미 계층에서 혼용되던 것을 표준화.
> 범위: **UI 라벨·사용자 노출 메시지·문서**를 이 표준으로 통일. 상태값(코드)·함수명은 유지하고, 전면 코드 리네임은 T4와 함께 점진적으로.

## 핵심 의미 모델

| 용어 | 대상 계층 | 뜻 | 코드 상태값(유지) |
|---|---|---|---|
| **확정 (confirm)** | 제출서(submission) | 추출 완료 시 견적 데이터를 **정본으로 동결**. 연계(/link) 스냅샷 확정도 이 계열(정본 버전 고정). | `extraction_status='done'`, `snapshot_version` |
| **채택 (accept)** | 클러스터 묶음(cluster) | 유사 품목 묶음을 **비교 기준으로 채택** → 카탈로그 등록. 개별 묶음 단위로 수행. | `catalog_clusters.status='accepted'` |
| **비교 단위** | 클러스터 레벨(가변) | 대/중/소/세분류·품목 어느 레벨이든 될 수 있음. "[분류] 비교 단위" 설정과 연동. | `submissions.compare_units` |

## 규칙

1. **제출서/정본 = "확정".** 추출·연계 스냅샷의 고정은 "확정"으로 표기.
   - 예: "확정 (스냅샷 저장)", "확정 v3", "미확정".
2. **클러스터 = "채택".** 묶음을 비교/카탈로그에 반영하는 행위는 "채택"으로 표기.
   - 예: "✅ 채택", "선택 일괄 채택", "채택된 클러스터", "채택 후 표시".
   - 되돌리기는 "재검토"(status→pending) 유지.
3. **상태값·함수명은 바꾸지 않음.** `status='accepted'`, `accept_cluster()` 등은 그대로.
   내부 주석/변수의 "확정" 표현은 T4 진행 중 점진적으로 정리.
4. **신규 코드부터 이 표준 적용.** 새 UI 문자열·flash 메시지는 위 규칙을 따른다.
5. **혼동 주의어:** "원화 확정"(통화 환산 확정)은 이 표준과 무관 — 그대로 둔다.

## 이번에 적용된 곳 (2026-07-10)

- `templates/compare/bid.html`: 클러스터 accept 관련 "확정" → "채택" (뱃지·버튼·일괄·툴팁·경고·주석). "원화 확정" 보호.
- `templates/catalog/clusters.html`: "확정됨" → "채택됨" 등 클러스터 문구 전부.
- `blueprints/compare.py`: 사용자 노출 flash("… 채택했습니다/채택 실패/채택할 클러스터…").

## 남은 점진 작업 (T4와 함께)

- `blueprints/compare.py`·`catalog.py`의 **내부 주석/docstring** "확정(accepted)" 표현.
- `submissions/match.html`의 "확정"(카탈로그 매칭 확정) — 매칭 계층 용어 정의 후 정리.
- 함수/변수명 리네임(accept_cluster 등)은 T4 물리/논리 분리와 병행.
