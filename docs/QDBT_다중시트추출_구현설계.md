# QDBT — 다중 시트 추출 (시트별 매핑) 구현 설계

> 대상: 로드맵 T6 · 문제: 여러 시트 선택 후 추출 시 마지막 시트만 남음
> 확정 범위: **시트마다 다른 매핑 지정**(서식 제각각) → 한 제출서로 통합
> 기준: 다중탭추출 설계서 map_config v2 + 현재 코드 실제 제약 반영

---

## 1. 근본 원인 (코드 확인)

현재 추출은 구조적으로 "한 번에 한 시트"만 다룬다.

1. **UI**: 시트 선택이 단일 `<select>` 드롭다운. `onchange`로 `?sheet=` 하나만 전환. "여러 시트 선택" 조작 자체가 없음.
2. **저장**: `map_config`가 `{sheet, mapping, header_row, ...}` — **시트 하나의 매핑만** 저장.
3. **추출**: `column_map_extract`가 단일 `sheet`를 받아, 저장 직전 **`delete_submission_items`로 기존 항목 전부 삭제** 후 새 시트만 삽입.
4. **기록**: `extracted_sheets=[sheet]` — 단일 시트만.

→ 시트 A 추출 후 시트 B 추출 시, B가 A를 삭제하고 덮어씀. **"마지막 시트만 남음"의 정확한 기전.**

---

## 2. 설계 목표

- 한 제출서에 **여러 시트를 각각 다른 매핑으로** 추출해 **누적 통합**.
- 시트별로 열 매핑·헤더행·비교단위·제외/네고 행을 독립 지정.
- 각 시트 항목을 하나의 트리로 병합(시트가 트리의 서로 다른 가지).
- 기존 단일 시트 방식과 **하위 호환**(스키마 변경 없음).

---

## 3. 데이터 모델 — map_config v2

### 3.1 구조 (시트별 매핑 딕셔너리)
```json
{
  "version": 2,
  "sheets": {
    "자재내역": {
      "mapping": {"1":"seq","2":"name","3":"qty","5":"price"},
      "header_row": 3,
      "mount_path": "자재",           // 이 시트 항목이 붙을 트리 상위 경로(선택)
      "compare_units": ["자재 > 서버"],
      "excluded_rows": [38],
      "nego_rows": []
    },
    "인력내역": {
      "mapping": {"1":"cat1","2":"name","4":"qty","6":"price"},
      "header_row": 2,
      "mount_path": "용역",
      "compare_units": [], "excluded_rows": [], "nego_rows": []
    }
  },
  "sheet_order": ["자재내역", "인력내역"]   // 트리 배치 순서
}
```

### 3.2 하위 호환
- `version` 없음(기존) → 단일 시트로 해석(현 구조 그대로).
- `version: 2` → 시트별 처리.
- 스키마 변경 없음: `map_config`(TEXT)·`extracted_sheets`(TEXT) JSON 확장만.

### 3.3 mount_path (트리 배치)
- 각 시트 항목의 path 앞에 `mount_path`를 접두(선택). 시트가 트리의 특정 가지에 배치됨.
- 미지정 시 시트명을 최상위로 사용하거나 평면 병합(정책 선택 — §6 미결).

## 4. 추출 흐름 재설계

```
[현재] 단일 시트: delete_all → extract(sheet) → insert
                 (재추출마다 전체 삭제 → 덮어씀)

[개선] 다중 시트:
  1. delete_submission_items(keep_nego=True)   ← 1회만 (전체 초기화)
  2. for 각 시트 in sheet_order:
       items = extract_by_mapping(fpath, 시트, 시트별_mapping, 시트별_header_row, ...)
       items에 mount_path 접두 + sort_order 오프셋 적용
       누적 리스트에 추가
  3. insert_items_bulk(submission_id, 누적_items)   ← 1회 (통합 삽입)
  4. extracted_sheets = 전체 시트 목록
  5. subtotal = 전체 잎 합
```

핵심 변경:
- **삭제는 루프 밖 1회**(시트별 삭제가 아니라 전체 1회 초기화).
- **삽입은 누적 후 1회**(시트별 삽입 결과를 합쳐서).
- `sort_order`는 시트 순서대로 오프셋(시트1: 0~n, 시트2: n+1~ …).

## 5. UI 재설계

### 5.1 시트 선택 → 시트별 매핑 관리
현재 단일 드롭다운을, **시트별 매핑 탭/목록**으로 확장.

```
[시트 탭]  자재내역 ✓ | 인력내역 ✓ | 총괄(제외) | + 
─────────────────────────────────────────────
현재 편집: [자재내역]
  헤더행: [3]   배치경로(mount): [자재]
  열 매핑: 1→번호  2→품명  3→수량  5→단가 …
  [이 시트 매핑 저장]
─────────────────────────────────────────────
포함 시트: 자재내역, 인력내역   [전체 통합 추출]
```

- 각 시트를 탭으로 전환하며 개별 매핑 지정.
- 시트별 매핑을 브라우저 상태(또는 임시 저장)에 누적.
- "전체 통합 추출" 시 누적된 시트별 매핑을 한 번에 전송.

### 5.2 점진적 접근 (구현 단순화)
1단계로 **시트별 매핑을 순차 저장 후 통합 추출**하는 최소 UI부터:
- 시트 선택 → 매핑 → "이 시트 추가"(map_config.sheets에 누적)
- 시트 반복 → "통합 추출"(누적된 전체를 추출)

---

## 6. 구현 단계

**1단계 — 백엔드 누적 추출 (핵심)**
- `column_map_extract`를 시트별 매핑 배열/딕셔너리 수용하도록 확장.
- 삭제 1회 → 시트별 추출·mount_path 접두·sort_order 오프셋 → 누적 삽입 1회.
- map_config v2 저장, extracted_sheets에 전체 시트.
- 하위 호환: 단일 시트 payload도 그대로 처리.

**2단계 — 재진입 복원**
- `column_map`이 map_config v2를 읽어 시트별 매핑 복원.

**3단계 — UI (시트별 매핑 관리)**
- 시트 탭 + 시트별 매핑 누적 + 통합 추출 버튼.

**4단계 — 검증**
- 2개 시트 다른 매핑 → 누적 통합, 합계 = 시트별 합의 총합, 트리 배치 정합.

---

## 7. 미결 사항 (착수 전 확정)

- **mount_path 정책**: 시트를 트리 어디에 배치하나? (시트명=최상위 / 사용자 지정 mount_path / 평면 병합)
- **비교단위 병합**: 시트별 compare_units를 어떻게 통합하나?
- **sort_order 충돌**: 시트 순서 = 트리 표시 순서. sheet_order로 제어.
- **중복 항목**: 다른 시트에 같은 품목이 있으면? (그대로 누적 vs 경고)
- **UI 범위**: 최소 UI(순차 추가) vs 완전 UI(탭 전환) 중 어디까지 이번에.

---

## 8. 리스크

| 리스크 | 대응 |
|--------|------|
| 시트별 sort_order 충돌로 트리 뒤섞임 | 시트 순서대로 오프셋 부여 |
| mount_path 없으면 트리 구조 모호 | 정책 확정(§7) 후 기본값 |
| 하위 호환(기존 단일 시트) 깨짐 | version 분기, 단일 payload 그대로 처리 |
| 통합 추출 중 일부 시트 실패 | 시트별 try, 실패 시트 표시·부분 저장 여부 결정 |

---

## 9. 권고 착수 순서

1. **1단계(백엔드 누적 추출)** 부터 — 근본 원인(삭제-덮어씀) 해소가 여기 있음.
2. mount_path 정책(§7) 확정 후 트리 배치 구현.
3. UI는 최소(순차 추가)로 시작, 이후 확장.

핵심: **삭제를 루프 밖 1회로, 삽입을 누적 후 1회로** 바꾸는 것이 문제의 직접 해결. UI·mount_path는 그 위에 얹는다.
