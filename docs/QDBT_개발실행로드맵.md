# QDBT — 개발 실행 로드맵

> 작성 기준: 환율 불변식 수정 완료 시점
> 목적: 종합 명세서 로드맵 + 정합성 감사 해소 과제 + 각 설계서 미결을 **하나의 실행 목록**으로 통합. 의존 관계·우선순위·결정 필요 사항 명시.
> 원칙: 위험 낮은 것부터, 선결 조건 지킨 순서로, 각 단계 배포·검증.

## 1. 진행할 작업 목록 (우선순위·의존 순)

### ── 그룹 1: 즉시 실행 (저위험·독립) ──

**T1. 도메인 보정 마이그레이션 1회성화** `✓ 완료`
- 매 서버 기동 시 실행되던 도메인 보정을 1회성으로 전환 (schema_meta 플래그 또는 선검사).
- 위험 낮음, 독립적. 명세서 §1.3.
- 선결: 없음.

**T2. 추출 시 unit_price_orig 항상 보존** `✓ 완료`
- 환율 역산 경로의 누적 오차 위험 제거 (명세서 §1.1 추가 완화).
- 추출 파이프라인에서 원통화 단가를 항상 저장.
- 선결: 없음. C3(불변식 수정)의 후속 보강.

**T2b. [버그] 클러스터 순서 드래그 시 테이블 섞임** `✓ 완료`
- **증상**: 클러스터 순서를 ⋮⋮ 핸들로 드래그하면 데이터테이블이 섞임. 섞인 행 삭제(새로고침) 시 원복.
- **원인(진단됨)**: bid.html 클러스터 순서 드롭 로직이 `insertBefore`로 **헤더 행(tr) 하나만** 이동. 그러나 한 클러스터는 헤더 행 + 업체별 항목 행 **여러 tr**로 구성 → 헤더만 옮겨지고 데이터 행은 잔류 → 섞임. 또한 `querySelectorAll('tr')`이 문서 전체 tr을 잡아 인덱스 계산 부정확.
- **수정 방향**: (1) 클러스터를 구성하는 tr 그룹 전체를 함께 이동(클러스터 id로 묶인 행 집합을 한꺼번에 insertBefore), (2) tr 탐색을 해당 tbody로 한정. 또는 드래그 후 서버 순서로 재렌더(부분 리로드)해 DOM 정합 보장.
- 선결: 없음. UI 후순위지만 실사용 방해라 즉시 그룹에 등록.

### ── 그룹 2: 구조 정리 (감사 해소, 이후 모든 기능의 토대) ──

**T3. 용어 표준화 (확정/수락)** `구조`
- 제출서 확정(confirm) vs 클러스터 수락(accept) 명칭 분리.
- 문서 전체 + 코드 변수/함수명 정리 범위 결정 필요.
- 선결: 없음. 이후 모든 작업의 용어 기준.
- 감사 문제 2.

**T4. 되먹임 분리 (핵심 구조 결정)** `구조·중대`
- submission_items = 견적 원본(동결 대상) / 별도 매핑 = 비교 결과(catalog_item_id·match_status).
- **결정 필요**: 물리적 분리(별도 테이블) vs 논리적 분리(동결 범위 축소).
- 기존 데이터 마이그레이션 수반(물리적 선택 시).
- 선결: T3(용어). 이것이 D3(버전관리)의 절대 선결.
- 감사 문제 1·4·5 동시 해소.

**T5. 합계 검증 공통 모듈** `✓ 완료`
- 4종 불변식(공급가액=트리=라인, Σ잎=묶음, Σ배치=노드소계, amount=단가×수량)을 단일 모듈로.
- 이후 D1·D2가 이 모듈 재사용.
- 선결: 없음. C3에서 ④는 이미 처리, 나머지 통합.
- 감사 §2.2.

### ── 그룹 3: 병합 기능 구현 (경계를 실증) ──

**T6. 다중 탭 통합 추출** `◐ 백엔드 완료(UI 남음)`
- 탭별 매핑(map_config v2), 삭제 1회 후 누적 삽입.
- **draft 상태에서만** 수행 명문화 (감사 문제 3).
- 선결: T5(합계 검증 — 통합 후 소계 정합).
- 설계: 다중탭추출 설계서 본문.

**T7. 다단(N레벨) 시트 연계 조립** `기능·고난도`
- 목록/트리/세부가 각각 다른 시트 → 드래그앤드랍으로 연계해 하나의 트리로.
- 4단계 프로세스(추출→자동제안→드래그조정·확정→확정데이터), 리뷰·확정 루프와 정합.
- 자동 연계 제안(seq·이름·소계) + 드래그 수기 보정 + 실시간 소계 검증.
- 공통 부품: 노드-잎 귀속·소계 검증기(T5 확장), 드래그 연계 UI.
- 확정 후 수정 시 버전 승격(T12 연동).
- 선결: T6(다중 시트 누적 추출), T5(합계 검증).
- 설계: 다중탭추출 설계서 부록 A(2레벨)·**부록 B(N레벨)** · 라이브목업(다중시트연계).

**T8. 묶음 펼치기 (다층 비교)** `기능`
- 잎 보존(role='leaf'), 2단계 계층(전략 A), 자동+수동 재매칭.
- **잎 보존 저장소**: 클러스터 멤버(참조·활성) — T4 분리 후 정합.
- 선결: T4(되먹임 분리 — 잎 재매칭이 원본 안 건드림).
- 설계: 묶음펼치기 설계서.

### ── 그룹 4: 버전 관리·프로세스 (기능 성숙 후) ──

**T9. 상태 모델 도입 (merge_status)** `프로세스`
- draft/review/confirmed, done 종속 규칙.
- 선결: T3(용어), T4(되먹임 분리 — 동결 실효성).
- 설계: 진화로드맵 부록 B.

**T10. item_id 동결 메커니즘** `프로세스·선결중요`
- confirmed 상태에서 재추출·변경 금지 가드.
- **결정 필요**: 상태 기반 가드 vs 트리거 vs 앱 계층 강제.
- 선결: T9(상태 모델). D3 버전관리의 선결.
- 감사 §2.1.

**T11. 리뷰·확정 4단계 루프 + 통합 검증 게이트** `프로세스`
- 시스템 제안→사람 수정→시스템 리뷰→사람 확정.
- 통합 검증: T5(합계) + 도메인 + 통화 게이트.
- 선결: T5, T9, T10.
- 설계: 진화로드맵 부록 B.

**T12. 확정 스냅샷·취소·다운로드** `프로세스`
- self-contained 스냅샷, 확정 취소(→draft), 버전 다운로드.
- 선결: T10(동결), T11(확정).
- 설계: 진화로드맵 부록 C.

### ── 그룹 5: UI·리팩터링 (후순위) ──

**T13. bid.html 리팩터링** `리팩터·후순위`
- 편집 UI 분리, compare 라우트 구획. 동작 불변.
- 선결: 없음(독립). UI 후순위로 보류.

**T14. 워크플로우 네비게이션** `UI·후순위`
- 입찰 중심 스텝퍼, 단계 이동. 목업 완료.
- 선결: T9(상태 모델 — 단계 표시).
- 후순위(사용자 지정).

## 2. 의존 관계 그래프

```
[즉시] T1, T2 ──────────────────────────────────── (독립)

[구조] T3 용어표준화 ──┬─▶ T4 되먹임분리 ──┬─▶ T8 묶음펼치기
                       │                    │
        T5 합계모듈 ───┼─▶ T6 다중탭 ─▶ T7 트리세부
                       │
                       └─▶ T9 상태모델 ─▶ T10 동결 ─▶ T11 확정 ─▶ T12 스냅샷

[UI]  T13 리팩터 (독립) · T14 네비 (T9 후) ───────── (후순위)
```

핵심 경로: **T3 → T4 → T9 → T10 → T11 → T12** (구조→프로세스 축)
병렬 가능: **T5 → T6 → T7** (병합 기능 축), **T1·T2** (즉시)

## 3. 권장 실행 순서

의존·위험·가치를 종합한 권장 순서.

1. **T1, T2** (즉시·독립) — 남은 즉시항목 정리.
2. **T3** (용어) — 이후 모든 작업의 기준. 저위험.
3. **T4 결정 + 구현** (되먹임 분리) — 최대 구조 결정. D3의 선결. **여기서 물리/논리 결정 필요.**
4. **T5** (합계 모듈) — 병합 기능의 토대.
5. **T6 → T7** (병합 기능) — 경계 실증.
6. **T8** (묶음 펼치기) — T4 후 정합.
7. **T9 → T10 → T11 → T12** (버전관리·프로세스) — 기능 성숙 후.
8. **T13, T14** (UI) — 후순위.

## 4. 즉시 결정이 필요한 사항

다음 작업 착수 전 결정 필요.

| 결정 | 영향 작업 | 선택지 |
|------|-----------|--------|
| 되먹임 분리 방식 | T4 (→ D3 전체) | 물리적(별도 테이블) vs 논리적(동결 범위 축소) |
| 용어 표준화 범위 | T3 | 문서만 vs 코드 변수·함수명까지 |
| item_id 동결 방식 | T10 | 상태 가드 vs DB 트리거 vs 앱 계층 |

**가장 중요**: 되먹임 분리 방식(T4). 이것이 버전 관리 전체 구조를 좌우하며, 물리적 선택 시 신규 테이블·마이그레이션을 수반한다.
