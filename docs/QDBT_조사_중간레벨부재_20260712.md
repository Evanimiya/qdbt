# QDBT 조사 보고 — 중간 레벨(중/소/세) 부재 시 트리 동작 (2026-07-12, 조사 전용)

> 요청: 대>중>소>세>품목에서 **중·소·세가 빠지고 품목이 대분류에 바로 붙는 경우**의 현재 동작 확인.
> 사용자 기억: "중/소/세가 **대분류 이름을 그대로 가져오도록** 규정했던 것 같다" — 실제 그런지.
> **코드 변경 없음.** 조사·재현·근거·권장안만.

## 1. 결론 요약

- 사용자 기억은 **실재한다** — 단, **한 경로(단일시트 `extract_by_mapping`)에서만**, 그리고
  '중/소/세 열이 **매핑됐지만 셀이 빈** 경우'에만 발동한다(`_prev_val` 상속, 아래 #2).
- 그러나 **경로마다 동작이 다르다(상충)**: 다중시트 스티칭(`stitch`)은 **복제하지 않고** 중간을
  떼어 **대 > 품목 직접**으로 붙인다. 즉 같은 의도의 입력이 **경로에 따라 다른 트리**가 된다.
- "중간이 없음"을 표현하는 방식이 **3가지가 공존**한다: (a) 직접 붙임, (b) placeholder(⟨미연계⟩),
  (c) 대분류 이름 복제. 어떤 게 나오는지는 *매핑/셀/시트 구성*에 따라 갈린다.

## 2. 현재 실제 동작 (재현 · 각 노드 depth·label·leaf)

| # | 입력 | 결과 경로 | 중간 레벨 처리 | 잎 | 근거 |
|---|---|---|---|---|---|
| **#1** | 단일시트 `[대, 품명]` (중/소/세 **미매핑**) | `재료비` (depth1) | **없음(직접)** — 대 > 품목 | 납블록 leaf | extract |
| **#2** | 단일시트 `[대,중,소,품명]`, 중·소 **셀 빈칸** | `재료비 > 재료비 > 재료비 > 납블록` | **대분류 이름 복제** (중=소=재료비) | 납블록(depth4) | `extract._prev_val` |
| **#3** | 단일시트 `[대,소,품명]` (중분류 **미매핑 gap**) | `재료비 > ⟨미연계·중분류⟩ > 차폐` | **placeholder** + `is_level_residual` | 납블록 | `_LEVEL_PLACEHOLDER` |
| **#2'** | 다중시트 passthrough `[대,중,소,품명]` 빈칸 | `재료비` (depth1) | **없음(직접)** — 복제 안 함 | 납블록 | `_stitch_passthrough` |
| **#4** | 다중시트 seq: 대목록(1,2)+세부(1.1.1), 중간 gap | `컴퓨팅 > GPU서버` (depth2) | **없음(gap skip)** — 대 > 품목 | GPU서버 leaf | `_stitch_seq` |

- **#2가 사용자 기억과 일치**: 중/소 자리에 **대분류 "재료비"가 그대로 복제**됨 →
  트리 `재료비(d1) > 재료비(d2) > 재료비(d3) > 납블록(d4)`, 캔버스 열 헤더 `대분류 | 중분류 | 소분류 | 품명`
  (중·소 열이 모두 "재료비"). **`is_level_residual` 플래그 없음 = 조용히(silent) 복제**.
- **#2' / #4 는 복제 안 함**: 다중시트 스티칭은 중간을 떼고 **대 > 품목 직접**.

## 3. 규칙 위치 · 상충 여부 (grep)

- **복제 규칙**: `src/extractors/extract_by_mapping.py:424‑425`
  ```python
  if not v and _prev_val:
      v = _prev_val   # 매핑된 깊은 분류가 비면 직전 상위값 상속(기존 동작)
  ```
  주석이 **"(기존 동작)"** — 최근 gap 수정 이전부터 있던 레거시. 매핑된 깊은 cat 셀이 비면 직전
  상위값(대분류)을 그 자리에 채운다 → 중/소/세에 대분류 이름 복제. **단일시트 extract 경로 전용.**
- **placeholder 규칙**: `_LEVEL_PLACEHOLDER`(extract·stitch 공유), `is_level_residual` —
  **매핑 안 된 중간 레벨(gap)** 자리에만 `⟨미연계·N분류⟩`를 넣는다(#3). 복제와 **다른 상황**.
- **stitch 경로**: `_stitch_passthrough`는 셀 병합복원만 하고 행간 복제/`_prev_val` **없음** →
  빈 상위는 residual(level_skip)로, 중간 부재는 **직접 붙임**(#2'). `_stitch_seq`는 없는 번호
  prefix를 **건너뜀**(#4).
- **상충**: `_prev_val`(복제)와 stitch(직접)는 **동일 입력에 다른 결과**를 낸다. placeholder(#3)는
  또 다른 3번째 처리. 즉 "중간 부재"에 대해 **일관된 단일 규칙이 없다**.

## 4. 어느 경로가 실제로 쓰이나

`submissions.py` `use_stitch`:
- **단일시트** 또는 mount_path 지정 또는 통화 매핑 → **T6 `extract_by_mapping`**(복제 #2 발동).
- **다중시트 + mount_path 없음 + (stitch=true 또는 자동·비통화)** → **T7 `stitch`**(복제 없음).

→ 사용자가 **단일시트에 대/중/소/품명 열을 매핑하고 중/소를 비우면** 복제(#2)를 본다.
다중시트(공종목록+세부 등)면 직접(#4).

## 5. 사용자 기억 vs 현재 · vs 이번 메시지 기대

- **기억("중/소/세=대분류 이름 복제")**: 실재(#2, extract). ✔ 단 경로 한정·silent.
- **이번 메시지 기대("중간을 떼고 붙어야 함, 예 대 > 품목")**: **직접(#1/#2'/#4)** 을 원함.
  → 사용자의 **현재 기대는 복제(#2)와 반대**(복제가 아니라 제거). 기억 규칙이 지금 기준으론
  바람직하지 않다고 보는 셈.

## 6. 바람직한 동작 — 3안 장단점

### (A) 대 > 품목 직접 (중간 제거) — **권장**
- 장점: 이번 사용자 기대와 일치("중간을 떼고 붙어야"). stitch 기본 동작과 **일관**. 잎이 얕은
  depth → leaf-aware 라벨로 **품명** 표기(오분류 없음). 가짜 노드 없음.
- 단점: 다른 제출서가 대>중>소>세>품목(전체 레벨)이면 **품목의 depth가 서로 달라** 열 정렬이
  어긋날 수 있음(비교 시). 단 품목은 여전히 잎.

### (B) placeholder(⟨미연계·중분류⟩ 등)
- 장점: **절대 depth 보존**(품목이 항상 같은 depth) → 시트 간 레벨 정렬·비교 정합. residual로
  사람에게 "여기 중간이 비었음" 신호.
- 단점: 평평한 데이터(진짜 대>품목)엔 **불필요한 잡음**·수동 해소 부담. 매핑 안 한 것을 억지로 채움.

### (C) 대분류 이름 복제 (현재 #2)
- 장점: depth 보존(B처럼)하면서 "미연계" 잡음 없이 트리가 "꽉 차" 보임.
- 단점: **가짜 노드**(재료비>재료비>재료비) — 실제 3레벨처럼 오인, **비교/클러스터링에서 같은
  분류명 중복**으로 오작동 위험, silent(플래그 없음). **이번 사용자 기대("중간 제거")와 정면 배치**.

## 7. 권장 · 확인 요청

- **권장: (A) 대 > 품목 직접**을 '중간 부재'의 표준으로 통일하고, `extract._prev_val` 복제(#2)를
  stitch와 동일하게 **직접**으로 맞춘다(경로 간 상충 제거). placeholder(B)는 **명시적으로 매핑한
  비연속 gap(#3)** 에만 유지(사용자가 그 레벨을 '의도'했다는 신호이므로).
- 단, (A)로 통일하면 **단일시트 extract의 기존 복제 동작이 바뀌는 큰 변경**이라, 회귀(실샘플/총액
  Δ=0는 유지되나 **트리 depth·경로 문자열이 바뀜**)·비교화면 영향이 있어 **착수 전 확인**이 필요.
- 대안: 비교 레벨 정합이 중요하면 (B)로 통일(단일시트도 placeholder). 트리 depth는 일정해지나
  잡음↑. → 어느 쪽을 표준으로 할지 **결정 필요**.
