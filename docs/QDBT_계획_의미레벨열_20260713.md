# QDBT 계획 — 연계 캔버스 '의미 레벨 열' 배치 (2026-07-13, 계획·확인용)

> 목표: '직접 붙임' 후 빈 중간 계층이 화면에서 보이도록, 캔버스를 **트리 depth**가 아니라
> **의미 분류 레벨(대/중/소/세/품명)** 고정 열 그리드로 배치. 빈 중간 열은 빈 칸으로 두고
> 부모→자식 **연결선이 빈 열을 가로지르게**(목업 `mockup_직접붙임_렌더.png`). 표시 전용·**Δ=0**.

## 1. 선결 확인 결과 (핵심)

- **각 노드는 자기 '의미 분류 레벨'을 모른다.** item/tree 노드에 `path`·`depth`(트리 중첩)만 있고,
  세그먼트별 레벨(대=1/중=2/소=3/세=4)이 없다. → 현재 캔버스는 트리 depth로 열을 나눠, '직접 붙임'
  시 빈 중간이 안 보임.
- **cat 모드(extract·stitch passthrough)** 에선 레벨을 **정확히 안다**(cat 역할 = `_lvl_val`/`levels`).
  예 `[대,소,품명]` → 재료비=1, 차폐=3. 지금은 조립 후 버려짐.
- **seq/band 모드**는 세그먼트가 cat 역할이 아니라 **번호/이름 유래라 레벨이 모호**. 예 C3 산출내역
  '1.1.1'(중-소 결합명)의 의미 레벨이 2인지 3인지 단정 불가.

## 2. 제안

### (a) 노드에 '의미 레벨' 실어주기 (구조 불변, 표시 메타)
- 각 item에 `path_levels`(JSON, 경로 세그먼트와 평행한 정수 레벨 배열) 추가.
  - **cat 모드**: `_lvl_val`/`levels` 키 그대로 → 정확(예 `[1,3]`).
  - **seq/band 모드**: 잎(품목)=품명 레벨(맨 오른쪽) 고정. 분류 세그먼트는 **가용 레벨 우선**,
    불명이면 **폴백(순서대로 1..N)** — seq 트리는 현행과 동일하게 보임(회귀 없음).
  - **잎(품목)**: 항상 품명 레벨(부품 있으면 부품). 트리 말단.
- 저장: `submission_items`에 nullable `cat_levels TEXT` 1열 추가(기존 `migrate_db` ALTER 방식).
  `insert_items_bulk` 기록, `build_items_tree`가 노드에 `level` 부여(세그먼트 i → path_levels[i],
  잎 → 품명). **금액·경로·depth·건수 불변**.

### (b) 캔버스 렌더 (표시 전용)
- 고정 열 = 레벨 1..maxLevel + 품명(사용자 지정 명칭 `S.levels`). 노드를 `node.level` 열에 배치.
- 빈 레벨 열도 항상 렌더(빈 칸). 부모→자식 SVG 연결선은 이미 좌표 기반이라 **빈 열을 가로질러** 그려짐.
- 잎 열 라벨 = '품명'(기존 leaf-aware 유지). 드래그/드롭·재지정은 그대로(경로 기준).

## 3. Δ=0 / 회귀

- `cat_levels`는 표시 메타 — 총액·건수·경로·depth 불변. 실샘플 15개 Δ=0 유지.
- seq/band는 폴백으로 현행과 동일 배치(회귀 없음). cat 모드 '직접 붙임'만 개선(빈 열 노출).
- 견고성 매트릭스 유지 + jsdom/HTML 스냅샷으로 열-노드 배치·연결선 검증.

## 4. 확인 필요 (착수 전)

1. **저장 위치**: `submission_items.cat_levels` **신규 컬럼**(권장, 깔끔) vs `map_config` 사이드(무마이그레이션).
2. **seq/band 레벨**: 잎=품명 + 분류는 **폴백(순서 1..N)** 으로 시작(현행 유지) 후 필요 시 정교화 —
   이대로 진행할지. (완전 정교화는 seq 번호 자릿수↔레벨 매핑 결정이 필요해 별건.)
3. 범위: 이번엔 **cat 모드 '직접 붙임' 빈 열 노출**에 집중(주 UX 페인)하고 seq는 회귀 없이 두는 것으로 OK인지.

→ 위 3가지만 확인해 주시면 작은 커밋으로 (a)→(b)→테스트 순서로 구현하겠습니다.
