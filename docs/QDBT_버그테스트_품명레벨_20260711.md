# QDBT 버그 테스트 보고서 — 품명이 '소분류'로 오분류 (2026-07-11)

## 1. 증상 (사용자 제보)

시트 매핑이 **[대분류, 중분류, 품명(name)]** (cat1+cat2+name, 소분류 cat3 없음)인데,
연계 트리가 **대 > 중 > 소** 로 보이고 **품명이 잎(라인아이템)이 아니라 '소분류' 레벨로**
표시됨. 기대: **대 > 중** 아래에 품명이 **잎 항목**으로.

## 2. 정확 재현

합성 픽스처 `[대분류, 중분류, 품명]` (소분류 없음)로 추출/트리/표시를 각각 확인.

| 지점 | 결과 | 판정 |
|---|---|---|
| `extract_by_mapping` | `path='재료비 > 기구부'` (depth 2), `name='납블록'`, placeholder 없음 | **구조 정상** |
| `stitch_sheets`(passthrough) | 동일 (`path='재료비 > 기구부'`, `name='납블록'`) | **구조 정상** |
| `build_items_tree` | `납블록` = **`is_leaf=True`**, depth 3, `재료비 > 기구부 > 납블록` | **구조 정상** |
| **연계 캔버스 열 헤더** | 3열: `대분류 \| 중분류 \| ` **`소분류`** ← 품명 잎이 이 열에 놓임 | **❌ 오라벨** |

→ **데이터 구조(추출·트리·`is_leaf`·금액)는 정상.** 버그는 **표시(연계 캔버스 열 헤더 라벨)** 에서
품명 잎 열이 **'소분류'로 표기**되는 것. (사용자가 "소분류로 분류됨"으로 인지한 지점.)

## 3. 근본 원인

`src/web/templates/submissions/_link_canvas.html` 의 열(depth) 헤더 라벨:

```js
function levelName(d){ return S.levels[d] || ('레벨' + (d+1)); }   // 고정 위치매핑
// S.levels = ["대분류","중분류","소분류","세분류","품명","부품","세부"]  (_level_names_for)
```

캔버스는 depth별로 열을 만들고 헤더를 `levelName(depth)`로 **위치(depth)만으로** 라벨한다.
이는 "분류 레벨이 항상 depth 0..N-1을 채우고 품명은 그 다음"이라는 가정인데,
**분류 레벨이 적은 시트(`[대,중,품명]`)에서는 품명 잎이 낮은 depth(0-based 2)에 놓여** 위치매핑상
`소분류`(index 2)로 오라벨된다.

- `[대,중,소,세,품명]`(분류 4레벨): 품명 잎 = depth 4 → `levels[4]='품명'` (**정상**).
- `[대,중,품명]`(분류 2레벨): 품명 잎 = depth 2 → `levels[2]='소분류'` (**버그**).

즉 **잎(품명)/가지(분류) 구분 없이 depth로만 라벨**한 것이 원인. (최근 gap/레벨보존
placeholder 수정은 **무관** — 추출 결과에 placeholder가 삽입되지 않음을 재현으로 확인.)

## 4. 수정

표시 전용, 구조·금액 불변(**Δ=0**). `_link_canvas.html`:

- 렌더 시 depth별 **'전부 잎'** 여부(`leafOnlyByDepth`)를 계산.
- 열 헤더를 `colHeaderLabel(d, leafOnlyByDepth)`로: 그 depth 노드가 **전부 잎이면 `'품명'`**,
  아니면 기존 분류레벨명.

```js
function colHeaderLabel(d, leafOnlyByDepth){
  return (leafOnlyByDepth && leafOnlyByDepth[d]) ? (S.levels[4] || '품명') : levelName(d);
}
// render(): S.nodes로 depth별 leafOnly 계산 → 헤더에 적용
```

효과:
- `[대,중,품명]` → `대분류 \| 중분류 \| 품명` (품명 잎이 '품명'으로).
- `[대,중,소,품명]` → `대분류 \| 중분류 \| 소분류 \| 품명`.
- `[대,중,소,세,품명]` → `대분류 \| 중분류 \| 소분류 \| 세분류 \| 품명` (**회귀 없음**).
- 혼합 열(같은 depth에 소분류 가지 + 품명 잎 공존)은 '전부 잎' 아님 → 분류레벨명 유지(보수적).

정상 케이스 회귀 없음(`[대,중,소,세,품명]`·`품명 미지정`(최말단 분류를 잎으로) 로직과 무충돌).
항목 연결 3단계 원칙(자동병합·종결 금지, 코드→LLM→사람)과도 무관(표시 라벨만 변경).
