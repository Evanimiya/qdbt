# QDBT 계획 — 제출서 기본(원) 통화 지정 (2026-07-13)

> 문제: 라인에 통화 표기 없으면 KRW로 간주 → 전체 외화 견적(예 USD)에서 FX 미적용.
> 요구: 제출서 '기본 통화' 입력/확인. 우선순위 **라인 명시 > 제출서 기본**. 비파괴·원화 재계산은 기존 재사용.

## 저장 (a)
- `submissions.source_currency TEXT DEFAULT 'KRW'` 신규 컬럼(자동 마이그레이션).

## 적용 규칙 (b, 확인창·되돌리기)
- `set_submission_source_currency(sid, cur, rate=None)`:
  - `source_currency = cur` 저장.
  - **cur ≠ KRW**: 통화 미태그(=KRW) 라인만 `cur`로 재태그 — `unit_price_orig`에 원통화 보존,
    rate 있으면 원화=orig×rate·amount=단가×수량(라인 정합), rate 없으면 `needs_fx`(원화 미확정).
    `fx_rates[cur]` 기록. (기존 `set_submission_fx_rate` 원화 덮어쓰기 패턴 재사용.)
  - **cur = KRW(되돌리기)**: 직전 source 통화로 재태그됐던 라인만 원복(orig→원화, fx=NULL, KRW).
  - **스코프**: KRW 라인 ↔ 기본통화만 이동. **라인 명시 통화(≠KRW·≠직전기본)는 불변** → 우선순위 보장.
  - `recompute_subtotal` 로 소계·대표환율 정합. 총액은 원화 확정치 기준(미확정=needs_fx는 제외/경고).

## UI (c, fx_rates 패널 연계)
- detail 통화·환율 패널 상단에 **"이 견적서 기본 통화" 드롭다운**(KRW·USD·EUR·JPY·CNY, 기본=source_currency).
  '감지된 외화 없음'이어도 항상 노출. 확정 버튼 → confirm 창(원화 재계산 안내) → `POST /<sid>/source-currency`.
- 기본통화 ≠ KRW인데 그 통화 환율 미입력 → 패널이 **그 통화 환율 입력 유도**(기존 fx_rates 행/경고 재사용).

## 미니 흐름
```
전체 USD 견적(라인 통화표기 없음) 업로드 → 추출: 전 라인 KRW로 간주(원화=표면값).
detail 패널: 기본 통화 [USD] 선택 + 확정 → confirm →
  전 라인 통화=USD·orig 보존, USD 환율 미입력이면 '원화 미확정' 경고 + USD 환율 입력 유도.
USD 환율 1,350 입력(기존 fx 행) → 원화=orig×1350 재계산. 총액 원화 확정.
되돌리기: 기본 통화 [KRW] → 라인 원복(원통화=원화), fx 해제.
```

## 파이프라인 일관성
- 라인 통화 결정 우선순위(라인 명시 > 제출서 기본)를 **추출 후 재적용 함수**에서 일관 적용
  (추출 시점엔 기본통화 미확정 → 사용자 확정 시 재태그). 집계(`recompute_subtotal`)·비교
  (`compare_*`는 item.unit_price_currency·fx_rate_used 기준)는 재태그 결과를 그대로 사용 → 일관.

## 검증
- create_app·문법·실샘플 회귀(Δ=0: KRW 기본이면 무변경). 되돌리기 왕복 시 원복 확인.
